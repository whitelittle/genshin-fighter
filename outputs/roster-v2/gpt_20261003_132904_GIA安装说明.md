# 三人顺序出战版：GIA 安装

2026-10-03 圆润 UI 修订：游戏标签为 ROUND 1、ROUND 2、ROUND 3；头像卡、阵容栏、展示框及操作底板改用原生圆角组合。技术资料、设计基线与素材入口已分开整理。节点协议与 B 容器索引规则不变，旧文件保留。圆角资源的官方显示与手机性能待验证。

本版为 45 位角色可选的双人测试候选。先选三位不同角色，分别用于 R1、R2、R3；先赢两局即结束比赛。没有一局内接力。若娜瓦按用户后续要求暂不制作。

## 文件与导入位置

交付文件名见同目录 `delivery.json`。实际交付目录为：

`%USERPROFILE%/AppData/LocalLow/miHoYo/原神/BeyondLocal/Beyond_Local_Export/`

1. 导入带 **A_三人阵容45角色** 的 GIA，它属于服务器控件模板。保留旧模板作为对照，不需要删除任何旧文件。
2. 已有 B 图元模板并且容器索引仍为 **1073741845** 时，直接沿用，不必再次导入 B。容器里必须有名为 **Pixel** 的图片控件。
3. 没有 B 时，导入本次 **B_通用图元模板** GIA，在客户端控件模板页找到它，查看右上角容器索引。
4. 如果 B 的实际索引不是 1073741845，在客户端脚本中找到 `local PIXEL_TEMPLATE_INDEX=1073741845`，只把数字改成 B 的实际容器索引。不要填 Pixel 图片本身的索引，也不要填玩家或控制实体的 GUID。
5. 脚本映射路径为 **lua/fighter_roster_v2.lua**。脚本挂在 A 内的 **FighterDemo** 容器上，不挂在黑色图片、LoadingScreen 或 B 的 Pixel 上。GIA 带有脚本；交付的单独 Lua 可用于检查或替换对应的导入脚本。
6. 把 A 放入现有界面流程，给两位玩家显示。新旧界面不要同时运行。按《节点安装说明》更新服务端信号后再双人测试。

这里使用固定 B 容器索引直接实例化，不需要额外手动绑定隐藏的 LoadingPixelTemplate 引用。只有改成索引 0 的自动引用模式时才需要该绑定；本交付不采用该模式。

## 本次界面行为

- 首页进入阵容选择；每页 10 个头像，共 5 页，结构可继续扩展到 50 位以上。头像格不显示长名字；选定后在左右 R 栏位和中央展示框显示名字。
- 两个中央展示框靠近；两边分别为 R1/R2/R3 阵容栏。蓝色表示 P1 已选、红色表示 P2 已选；同角色被双方选择时两侧都有颜色标记。
- 一方只能选三位不同角色。点击已选头像或自己的 R 栏位可撤回，后面的角色向前补位；锁定后不能修改。
- 选人页不显示地图。P1 随机抽取一张地图并同步，比赛内保持同一地图。大树/神像、蒙德城门/教堂、风龙废墟高塔为本次恢复的关键地标。
- 双方都锁定、并完成当前场角色加载后才开战。R2/R3 开始前再次黑屏加载对应角色，卸载上一场角色数据和多余控件；不提前常驻六个角色。
- PC 隐藏触控摇杆和攻击按钮；手机保留。H 打开指令表，E 特殊技，Q 必杀；J 轻攻、K 重攻、L 防御、空格跳跃、S 蹲伏。
- 结算后双方都选择再战才开始；一方返回首页或重新选人，另一方也退出当前比赛。退出是回首页，不是关闭原神。

## 排查

加载失败提示 B 索引：核对 B 容器索引与 Pixel 名字。

只见静态黑屏，派蒙/百分比都不动：检查 lua/fighter_roster_v2.lua 映射及 FighterDemo 的脚本挂载。

头像有了但对方阵容不更新：检查 FighterTeam/FighterTeamOut 的 **11 个整数**，不要继续使用旧 FighterSelect 的六参数。

加载到 100% 仍不开战：检查双方 Ready=2、Epoch 一致、FighterJoin/FighterJoined 都带 Epoch。

R1 正常、R2 卡住：检查新 Epoch 的清理与再次开战，不要把 Started 永久设为 true 后挡住后续 Join。

## 验证边界

【模拟器验证】抽样检查三场换人、A/E/Q 输入、结算、双方再战、退出释放，以及手机宽屏和 4:3 选人布局。原有防御高低段、刻晴/迪卢克 E/Q 和延迟丢包回滚检查通过。

【制作候选】新增角色采用 12 个关键姿势，另有 8 个状态使用姿势代用；E/Q 根据资料做格斗改编，不是原作完整 RPG 机制或逐帧完成的正式动画。中央选人展示采用完整头部图，不常驻站立动画。

【真机待验证】本次尚未在官方编辑器导入或手机运行；实际读条时间、帧率、长时间联机和平衡仍需用户反馈。
