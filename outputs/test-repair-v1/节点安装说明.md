# 第一批完整测试版：节点安装与迁移

GIA 交付的是界面模板及 Lua，**没有附带已安装的官方服务器节点图**。本地 serverLogic 用于模拟器。本页是千星编辑器的手动接线方案，替代旧版六参数 FighterSelect；Frames 的转发逻辑继续保留。

## 挂载和变量

沿用固定控制实体 **1077936129** 保存公共状态。P1/P2 是玩家实体引用，在场玩家列表实测序号为 0、1；不要把玩家实体值 3/5 和控制实体 GUID 混用。

节点图挂在控制实体上时，自身实体就是控制实体；若图仍挂在玩家上，所有公共变量的目标实体都接“以 GUID 查询 1077936129”的结果。同一条链不能一半写玩家、一半读控制实体。

建议变量：P1/P2（实体）、Epoch=1、Stage=1、Round=1、Wins1/Wins2=0；每位玩家各有 Role1/Role2/Role3=0、Ready=0、Revision=-1。这些状态的目标实体相同。

## 信号定义

|方向|信号|参数顺序与类型|
|---|---|---|
|客户端→服务端|FighterHello|无|
|服务端→客户端|FighterSeat|Slot：整数|
|客户端→服务端|**FighterTeam**|**Slot、Role1、Role2、Role3、Ready、Stage、Epoch、Revision、Round、Wins1、Wins2：11 个整数**|
|服务端→客户端|**FighterTeamOut**|上述 11 个整数，顺序完全相同|
|客户端→服务端|FighterJoin|Epoch：整数|
|服务端→客户端|FighterJoined|Epoch：整数|
|客户端→服务端|FighterFrames|Slot、FirstFrame、AckFrame：整数；Payload：字符串；Epoch：整数|
|服务端→客户端|FighterFramesOut|上述 5 个参数，顺序相同|
|客户端→服务端|FighterFlow|Slot、Action、Epoch、Revision：4 个整数|
|服务端→客户端|FighterFlowOut|上述 4 个整数，顺序相同|

Slot=1/2；角色 ID 见同目录《角色列表与改编》。角色未选时为 0，已确认阵容必须是三个非零且不同的 ID。Ready：0 选择中，1 锁定/加载中，2 加载完成，3 返回首页。Stage=1–210（三张不同国家背景的排列码），Round=1/2/3。Action：1 再战投票，2 重新选人，3 回首页。

## 1. 席位：保留已成功的入口

`监听 FighterHello → 取在场玩家列表 → 长度判断 → 列表第0项/第1项 → 保存 P1/P2 → 向对应玩家发送 FighterSeat(1/2)`。

长度不足 2 不取第 1 项；一位玩家存在时也可先给他席位 1。每次 Hello 可重发席位，不能每次 Hello 都清空阵容和比赛状态。

发送目标直接接正确的玩家实体。连续发给 P1 和 P2 已有此前用户真机成功记录，无需增加人为延时。

## 2. 阵容同步：新增 FighterTeam

`监听 FighterTeam → Slot 与发信玩家校验 → 参数范围/重复角色校验 → Epoch/Revision 判断 → 保存该席位 11 参数状态 → 分别向 P1、P2 发 FighterTeamOut(11参数)`。

先用一次完整打印确认“信号来源实体”端口在当前编辑器确实是发信玩家，再比较 P1/P2。不要未经核验把事件源实体或获取自身实体当作发信玩家。

规则：

1. Epoch 小于保存值：丢弃。
2. Epoch 大于保存值：先清空两席位 Ready 和 Revision，再采用新 Epoch。**不能仅清空发信席位**，否则上一场 Ready=2 会被误用。
3. 同 Epoch、同席位 Revision 小于保存值：丢弃。相等版本可重新广播快照以补回包，不重复做额外业务副作用。
4. Role1/2/3 合法范围 0–45；Ready=1/2 时三个角色都非零且不同。
5. Stage、Round 和比赛分数由 P1 的快照采用；P2 的同名字段只作镜像，不改写 P1 的地图或分数。本原型为客户端回滚，正式防作弊不在本次范围。
6. 有效快照向两位玩家分别发送。11 根数据线从监听端口原样接到发送端口，不能把 Role2/Role3 与 Ready 错位。

客户端等待阶段每秒重发当前快照，用于补漏。选人图像只在选择或翻页时更新，不靠高频网络包驱动动画。

## 3. 开战门槛：每个 Epoch 都可再次进入

`监听 FighterJoin(Epoch) → 两玩家存在 → 请求 Epoch 等于公共 Epoch → 两席位 Ready 都为2 → 向 P1/P2 发送 FighterJoined(Epoch)`。

仅两个人进入房间、或 Ready=1，均不能开战。重复 Join 允许重发同 Epoch 的 Joined，客户端忽略重复开始。**不要用一个永不复位的 Started/IsInit 布尔量阻止 R2、R3 或再战。**

## 4. R2/R3 的交接由 P1 发布

R1 结束后，两端继续推进结算间隔。P1 到达边界后增加 Epoch，发布 Round=2、累计 Wins1/Wins2 以及相同三人阵容；双方加载各自 Role2。P2 即使还没看到最后几个旧帧，也根据 P1 的新 Epoch 快照采用回合和比分，旧 Epoch 帧随后丢弃。

双方加载完成，Ready=2，新一轮 FighterJoin → FighterJoined 后，从该场的新回滚会话开始。R3 同理使用 Role3。先赢两局直接结算，可能不打 R3。平局重赛当前 R，不消耗下一个角色。

服务器不需要另写“倒下一人立即换人”分支；这里每个角色对应一场完整回合。

## 5. 输入中转：保留五参数

`监听 FighterFrames → 校验来源/Slot/Epoch → Slot=1 转发给P2，Slot=2 转发给P1 → FighterFramesOut`。

FirstFrame 和 AckFrame 不接反；Payload 必须是原始字符串，不拼接说明、不解析改写。不操作的玩家仍需要转发空输入/确认包。旧 Epoch 输入丢弃。

## 6. 再战、重选、退出

`监听 FighterFlow → 校验来源/Slot/Epoch → 向两人原样发送 FighterFlowOut(四参数)`。

Action=1：投票，客户端等待双方都投票，并定期重发。双方同意后新 Epoch、Round=1、比分清零、重新加载阵容 R1。

Action=2/3：停止当前对战；下一 Epoch 的 Ready=0/3 快照同时记录重选/首页状态，应接受并广播。取消时可先收到新快照再收到旧 Epoch 的 Flow，这是正常乱序；不要因旧 Started 状态挡住退出快照。

## 7. 打印和抽样排查

每次打印一整条，避免一条信息拆很多节点：

`TEAM | 来源=<实体> | Slot=2 | R=11,41,32 | Ready=2 | Map=1 | Epoch=3 | Rev=8 | Round=2 | Score=1:0 | P1=<实体> | P2=<实体>`。

Frames 打印抽样，不每帧打印 Payload。检查顺序：双方席位 → 双方三个栏位同步 → 单方锁定不开战 → 双方 Ready=2 → Joined 同 Epoch → R1 正常输入 → R2 新 Epoch → 结算单方再战等待 → 双方再战 → 单方退出带动另一方。

【模拟器验证】上述主流程已有抽样通过记录，见 verification.json。【官方节点待验证】本页尚未在用户编辑器接线和实测。

## 本次相对旧节点的修改清单

角色帧替换不增加技能信号。已有roster-v2十一整数Team协议可复用；只有旧Hello/Join/Frames图的，必须新增Team和Flow两条链，并为Join/Frames补Epoch。

1. 保留席位与输入中转；列表序号0/1，客户端Slot1/2。
2. 新建FighterTeam监听，验证来源与Slot，接收11整数，同代Revision去旧，更新公共实体对应玩家阵容/准备状态，再将FighterTeamOut发送给P1和P2。发送目标是玩家引用。
3. 修改FighterJoin开战门槛为同Epoch、两端Ready=2；不能只有在场人数>=2，不能永久Started=true后阻挡新回合。
4. 新建FighterFlow监听，校验后广播4整数；Action=2任一人返回选人，两端均响应新Epoch清空旧输入与准备状态。
5. Frames双方均转发，静止玩家仍发中性输入及确认；不增加延时节点。

接线主链：Hello→Seat；Team→双方TeamOut；Join→双Ready门槛→双方Joined；Frames→对方FramesOut；Flow→双方FlowOut。每次关键事件合并一条日志，输入只抽样打印。

角色ID保持旧名单：绮良良13，绫华14，绫人15，一斗16，心海17。不要误把名单内序号当成第一批顺序。游戏标签为ROUND 1/ROUND 2/ROUND 3；下文R1等仅文档简称。

## 本轮必须修改的节点

FighterTeam / FighterTeamOut仍是11整数，顺序不变。第6个Stage从原1–3改为**1–210整数**；若原图有“Stage≤3”分支，改为“Stage≤210”。不要把第6个字段改为本回合背景ID，也不要每次转发重新随机。P1开始选人时生成顺序码，双方使用同一Stage和Round在客户端展开，三张背景不重复。服务器采用P1的Stage，给两端原样转发。

其余Hello→Seat、Team→双方TeamOut、Join→双方Ready=2→Joined、Frames→对方、Flow→双方不新增参数。碰撞与读条在客户端Lua，无需新增服务器逐帧判定节点。中高精度预览不改服务器协议。

这是接线说明；本包不包含可直接安装的官方服务器节点图。
