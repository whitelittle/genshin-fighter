# r33 正式版安装说明

这是从已确认归档 3e508011db14 重新合并的版本，仅标清，仅开放雷电将军与纳西妲。默认从开场、标题和主菜单进入，保留单人街机、对战电脑、训练、选人选场、VS、战斗、结果、再来和联机入口。

## 已经有可运行的工程：推荐只替换一个 Lua

1. 打开原 GF_HOST 挂载的游戏主脚本，将内容全部替换成根目录的 **genshin_fighter.lua**。
2. 保留现有 UI、图片模板和 GFV2 服务端节点，确保只有这一个游戏主脚本在执行。
3. 这个 Lua 已包含标清素材，不需要 gf_art_sd.lua 或 gf_art_hd.lua。确认没有其他脚本引用后，删除旧高清素材映射，以及已不再使用的旧标清模块映射，释放项目容量。

推荐版使用内置模块，不依赖官方客户端跨文件 require。不能把 optional-modular 中的主脚本与根目录主脚本同时挂载。

若偏好用 GIA 更新脚本，可用 GF_FORMAL_LUA_ONLY.gia 导入一份脚本，再挂到原 GF_HOST 并解除旧主脚本挂载；该文件不带界面，不会自动替换旧挂载。

## 新建工程

1. 导入 GF_IMAGE_TEMPLATE_B.gia 图片模板。
2. 导入 GF_FORMAL_A.gia 主界面；确认其中游戏脚本挂到原 GF_HOST 控件，不要挂到其他容器。
3. 核对 **B 图片模板在当前工程中的实际资源索引**。脚本按 GF_IMAGE_TEMPLATE_INDEX 参数、GF_DYNAMIC_IMAGE_TEMPLATE_INDEX、归档默认值 1073742224 的顺序读取。原确认工程使用 1073742224；新工程若不同，在主 Lua 顶部新增 `GF_DYNAMIC_IMAGE_TEMPLATE_INDEX=实际索引`。不要把控件 ID 或文件内 GUID 当成实际资源索引。

A 保持原 UI 二进制，仅替换了脚本；B 保持原二进制。原本的容器挂载错误会导致全界面不可见，替换源码不能替代正确挂载。

## 可选多文件版

只有希望主文件仅管理逻辑时才使用 optional-modular：导入 GF_ART_SD.gia 注册标清素材，主脚本换成该子目录的 genshin_fighter.lua；素材文件不挂到控件。路径必须是 default_import_file/gf_art_sd.lua。模拟器已验证跨文件 require，但未验证你的官方客户端，遇到模块加载失败请使用根目录单文件版。

## 按键

## 美术、图元池与诊断

重点美术步骤见 ART_STANDARD.md：拟合后统一一像素深色轮廓；草神加强内部色块对比，雷神保留认可配色；头像沿用原适配。高清包和画质切换已删除，Lua 中也不保留高清数据。

池容量基线 14000，极端上限 20000。低余量预警即创建，每帧分批增加；战斗中不销毁，仅回合结束/对局结束的安全阶段回收，不低于基线。描边造成的新增图元已经纳入实际池测试。

F9 在战斗中开启诊断，日志每 120 个采样输出 GF_PERF：场景、平均/最大回调间隔、超过 33.3ms 次数、UI 写入估计、池总量/余量、累计创建/销毁。关闭诊断时不采样。这是排查掉帧与扩池关系的探针，不是 GPU 性能测量；不能用浏览器 FPS 替代真机结果。

## 联机

已有 GFV2 服务端节点继续保留。同一官方关卡的两位玩家进入“对战模式 → 联机对决”，连接后选人并准备。全新工程按 GFV2_Online_All_Nodes.html 配置服务端；该 HTML 是节点说明，不是服务端 GIA。浏览器保留联机入口和握手过程，但没有官方关卡服务端，不能当作两台设备联网成功。
