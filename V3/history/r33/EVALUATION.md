# r33 评价

## 可保留

| 项目 | 依据 | 复用方式 |
|---|---|---|
| GFV2 网络诊断、握手路径 | 自动流程通过 | 从稳定基线逐项 cherry-pick/重做 |
| 字体 20、行高、池化文字、VS 480 宽、根节点拉伸 | 3e 已确认内容 | 以 3e 文件为源，避免重写 |
| 回合结束/对局结束回收图元 | 动态池压力测试 | 先测真机创建成本，再决定预热量 |
| 早死清理、三段命中和命中确认状态 | 逻辑测试通过 | 保持动作逻辑与视觉帧分离 |
| HTTP gzip 字节恢复 | 资源字节校验通过 | 独立保留，不与战斗图元混合 |
| 原 V2 weighted OKLab、premultiplied alpha、共享 painter | 仓库源代码核实 | 作为新美术管线基线 |

## 负优化：下一轮默认撤销或不带入

| 项目 | 现象/原因 | 决定 |
|---|---|---|
| HD 包、160 采样、HD 池 24000/32000 | 用户明确取消，容量接近上限并卡顿 | 撤销 |
| 304 张大幅插帧 | 每张图增加 UI setter/批处理压力，真机掉帧风险高 | 撤销为默认；只保留原始关键帧 |
| 强制 1px/2px 描边和内部调色板扩展 | 草神 2px 过厚；描边提高每帧像素量 | 仅作为可选后处理，经设备门禁 |
| 默认大量预热图元 | 没有实机收益证据，扩大启动和内存压力 | 回到已测基线，按预警小批创建 |
| 简化采样和取消原 V2 分层 painter | 破坏原 V2 已验证的角色质感和边缘 | 恢复原 painter，另做性能对照 |

## 待验证而不提前归因

真机掉帧可能来自帧数、图元 setter、池创建、批处理、Canvas 绘制或组合效应。当前探针只统计 Lua dt/写入估计，不是 GPU/FPS 基准。下一轮必须在同一设备、同一场景、同一输入脚本下做单因素对照。
