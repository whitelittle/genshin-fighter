# 移动端开始页无法进入 · 单例反馈

2026-10-14。匿名玩家反馈卡在“按任意键开始”，目前仅一位用户提到。设备型号、系统、游戏版本、实际挂载脚本及是否动画继续均未知，不判断为机器问题或确认程序故障。本批仅检查与提出定位方案，未修改触摸入口。

源码确认：`runtime/source/menu/gf_scene_title.lua`建立覆盖屏幕的透明按钮，超过0.6逻辑秒后通过click进入菜单；键盘路径也可触发。移动端标题页只提供click处理器，没有down/up兜底。`runtime/source/input/gf_input.lua`只有成功调用`ev.GetUIPos()`并得到数值坐标才执行处理器；取坐标失败直接返回，没有标题页可见提示。标题页本身不需要触摸坐标才能开始。

待验证推断：若某设备的CursorClick未送达、点按包含滑动被取消，或click事件GetUIPos失败，会表现为动画仍正常但无法进入。透明控件遮挡、输入按钮池/监听绑定失败同样需排查；当前没有实际设备日志证明上述任一原因。若提示不再闪动，优先查OnUpdate异常、加载阻塞或进程停顿，而非只查click。

最小复核：记录提示是否持续闪动、等几秒后轻点屏幕不同位置是否有效、点击是否出现切页动画；记录机型/系统/游戏版本和挂载脚本标识，同账号另设备或同设备重进作为辅助对照。单例不代表不存在程序兼容问题，重进恢复也不能证明机器故障。

后续候选设计：标题页保留click，并提供去重的触摸松开/按下兜底；无坐标的开始确认走独立入口，不放宽战斗摇杆等需要坐标的路径；按下→拖出→松开、快速连点、多指、横竖屏与界面切换分别测试，避免一次触摸连续穿透后续菜单。先加低频事件/取坐标/切页诊断，再根据真实失败原因修订；不能把模拟器触摸通过当该设备已验收。

当前PC性能候选未修改标题页或输入模块。两项反馈分别记录。
