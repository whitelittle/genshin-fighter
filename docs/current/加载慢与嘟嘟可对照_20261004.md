# 加载慢与嘟嘟可实现对照

2026-10-05后续决策优先见[加载优化讨论与修复清单](加载优化讨论与修复清单_20261005.md)：用户明确取消派蒙，只保留进度条；下文移动派蒙或降低帧率为历史建议，不再执行。目前用户要求先讨论，不开发。

观察：用户反馈手机需几分钟，后续PC也每秒仅推进少数任务。截图显示准备本回合角色67%，11894/17601。静态截图不能量化每秒速率；速率依据用户反馈。17601为任务总数，混合解码、回收、创建和背景属性写入，不等于图元数量。

只读参考嘟嘟可地图1.0 map5x5.lua、战斗0811实现的chunked-prefix/suffix.lua及其成功导出源码。未修改嘟嘟可工程。用户已有加载较快的体验，但旧归档没有量化同设备耗时。

不能把4ms/5ms或手机48/PC96单独认定为几秒与几分钟差距原因。两工程都有逐项os.clock计时。单一父容器子级规模是否放大布局成本是待验证推断，不当作平台事实。压缩减少文件体积，不保证减少运行准备时间。

建议下一次修订按顺序：缓存加载提示控件引用、进度布局只在画布变化时设置、派蒙加载期仅移动整组或降更新频率；显示解码/创建/回收/绘制阶段和每秒完成数、更新频率、时长；保持同一素材和9000档对照一次；如确认大父容器创建速度随数量下降，再测试背景按固定规模分组；最后考虑加载常用动作后补其余数据，但必须保证所有战斗事件与回滚所需动作数据可用。

所有上述修订尚未实施，真机根因尚未隔离。本地模拟器速度不能作为官方千星控件创建耗时。
