## 本轮已产出

独立探针 `outputs/motion-production/index.html`；正常比例待机对照 `proportions.html`。每位48张，共240张姿势：基础16、攻击关键姿势16、普攻与特殊技连接16。普攻与特殊技各8张实际生成帧，按现有起手、有效、收招分配保持时长。蹲防、受击、倒地等短动作仍以关键姿势为主，不能称所有动作已完成完整逐帧补画。

探针支持16类动作、连续流程、单步、拖动、四分之一速度、镜像、轮廓和锚点检查、设计数据导出。必杀模型仅首击接触成功后进入60逻辑帧演出，终击结算主要伤害；防住、距离不足或空挥不锁对手。纳西妲终击30伤害为探针临时数值，不是原作事实或正式平衡。模型未接入正式联机。

生成使用内置 imagegen；完整实际提示词分别保存为 `prompts.json`、`repair-prompts.json`、`connection-prompts.json`、`extra-prompts.json`、`normal-proportion-prompt.json`。保留所有原图与失败返修。迪卢克攻击v2/v3产生17个主体，未按16帧直接接入；原v1被裁举剑帧用独立单姿势返修。连接图末帧有边缘风险，E收招末姿势改回基础待机。

## 运行数据与证据

只读alpha/连通区域审计：`source-audit.json`。裁切与锚点：`source-manifest.json`，按实际独立主体记录，不均分大图；自动脚底估计仍需人工复核。拟合使用已有静态工具内核：96像素身体基准、32色、平均采样、alpha门槛220、无重叠矩形。拟合PNG在 `frames`，图元数据在 `data`。没有为了达硬上限默删轮廓，也没有删除源文件。

单角色共享池峰值为1867–2478个矩形；这是候选数据，不是手机帧率。JSON与gzip分别保存，压缩文件仅供运输/归档；没有声称千星Lua已经实现gzip解压。正式接入需使用目标平台支持的存储格式与实际客户端池回收流程。

**设计模型验证**：240张拟合重建、3309个姿势时间采样、30个必杀分支检查通过，见 `verification.json`。事件时间与渲染回调分离。**浏览器观察**：姿势加载、八帧普攻、必杀终击、防住零伤害、空挥、倒地/镜像与正常比例对照已抽样。**真机观察**：本轮无新证据。**待验证推断**：动作完整流畅、各帧持械/服饰一致、自动锚点是否无漂移、GIA导入、手机负载、回滚与联网演出均未通过最终验收。

正常比例版目前只有纳西妲待机对照，不冒充已经完成整套正常比例动画，也不直接替换原版。其余角色三批制作前，应以当前对照与动作问题修订模板。

## 可重建流程

1. `python work/audit-motion-production.py`：只读源图审计。
2. `python work/build-motion-manifest.py`：输出独立裁切、动作与锚点候选。
3. `node work/build-motion-production.mjs`：拟合PNG、帧数据、每角色池峰值与压缩报告。
4. `node work/verify-motion-production.mjs`：验证映射、时间分支、批次不重叠，输出姿势检查图。
5. `node work/build-motion-proportion.mjs`：独立正常比例待机对照。
6. 浏览器实际检查，再决定哪些帧通过美术验收；不能以脚本通过自动给全部图批准。

Node需已有 `@napi-rs/canvas` 与静态工具内核；当前脚本使用本机已有依赖路径，换机需调整。构建只写本轮生成目录，不覆盖正式战斗或旧GIA。今后每批独立目录、提示词、失败记录、动作映射与验收报告；整改只影响该批候选。
