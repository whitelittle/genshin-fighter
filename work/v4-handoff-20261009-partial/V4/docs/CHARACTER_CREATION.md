# V4 角色创建说明

2026-10-08 最新设计要求。适用于隐藏14名角色，与 V3 的技术、美术和验收标准共同执行。按最新用户授权，全部14名角色均推进至额度不足，可跨角色先做候选，动作逐批迭代；本说明及设计卡不代表已接入或通过真机验收。

## 先理解角色，再制作动作

每个角色先提交一张设计卡，回答以下问题，再写生成提示词。不能把通用剑招换颜色当成新角色，也不能先画完25组才考虑玩法。

| 指标 | 创建说明必须写清的内容 | 验收依据 |
|---|---|---|
| 人设与世界观 | 性格、身份、表演气质；怎样移动、进攻、防御和对待助手 | 动作能解释为什么属于这个角色，不与人设冲突 |
| 原作依据 | 官方技能、演示或剧情的来源；实际看过的片段及时间点 | 区分已核对事实、待核对参考和格斗改编；不编造观看记录 |
| 核心识别 | 最重要的2—3个角色符号，以及普通攻击如何使用它们 | 识别不只依赖服装或Q；轻重攻击也有专属表达 |
| 格斗定位 | 擅长距离、节奏、优势和弱点；对手怎样躲避、防御、打断或反击 | 有明确应对办法，不能用世界观理由给无条件无敌或全屏命中 |
| 武器必要性 | 是否常驻持武器，何时出现/收起，空手时如何进攻 | 原作武器类别不强制待机持武器；手部、道具状态和动作切换连贯 |
| 基础姿态 | 空手/持物待机、站防/蹲防、步态、跳跃及重心 | 先验证自然待机和真实步态，脚底稳定，无抽搐和姿势瞬跳 |
| 逐招编排 | 身体动作、助手/武器动作、打击位置、起手/有效/收招 | 每招的动画意图与实际攻击盒、命中时刻一致 |
| E / Q / 投技 | 专属机制、分支、双方编排和可读提示 | E不是换色通用弹；Q命中确认后演出；投技有被投者全过程 |
| 分层与预算 | 身体、武器、助手、水效/斩影、背景的归属及并发峰值 | 装饰不产生额外伤害；同时统计双方，避免大量临时创建销毁 |
| 风格与证据 | 母版、比例、视角、调色板、锚点、提示词、源图/拟合/播放证据 | 向已认可雷电/纳西妲统一画风，逐层标记实际完成程度 |

角色差异不等于每个人都带召唤物。芙宁娜围绕沙龙伙伴；其他角色必须从各自人设、力量来源和原作招式提炼玩法，不能复制三小只模板。

## 把原作改编为格斗招式

保留动作气质与角色识别，不照搬开放世界的冷却、自动追踪、治疗、生命消耗、养成或元素反应。改编动作明确标为本项目设计。例如抱海马喷水、投出章鱼伙伴、舞台连续攻击是芙宁娜格斗改编，不能写成原作已存在的动作。

每张动作卡至少包含：actionId、输入/前置条件、起手/有效/收招的60Hz tick、伤害与硬直、击退/击倒、攻击与受击盒、低/中/高属性、移动、取消条件、命中ID、助手事件、显示帧顺序与锚点、落空/防御/命中/受击中断分支。未定数值明确写待调，不把动画帧数当逻辑tick。

- 普通攻击、蹲攻、空攻都要说明真正的伤害来源。长水流/武器有可读边界；光晕和装饰不等于攻击范围。快速移动攻击验证连续扫掠，不允许穿过目标漏判。
- 多段每段有独立命中ID及防重复记录；同一段不能因多张显示帧、多个助手重叠或回滚重播重复结算。确定性模拟管理位置、阶段和事件；新增状态加入copy/snapshot/hash。
- E可由多名助手合演，但必须声明是一次合击还是多段。不能把三份水效自动算成三倍伤害；追踪、滞留、投射物碰撞及主人受击后是否继续均须明定。
- Q借鉴已认可纳西妲的展开领域思路，但场景与动作要属于新角色。只在有效命中确认后进入完整舞台/领域演出；落空、防御走可惩罚的短分支。注明总伤害段数、每段时刻、双方锁位和演出结束恢复。
- 投技包含抓取成立、双方接触锚点与锁位、牵引/抬起/转体/释放、被投、落地和起身；说明距离、可抓状态、逃脱窗口及墙边/体型差异。助手参与也不能省略双人接触和被投动作。

## 武器、助手与站立帧

不强制每个人持剑站立。先选择符合角色定位的空手/持物姿态，再设计防御与攻击转换。武器只在需要的动作出现时，明确出现/收起时刻和挂点；不能突然消失、变长或多出手臂。

芙宁娜当前方向是**空手、优雅指挥式待机**，普通攻击伴随海薇玛夫人、乌瑟勋爵和谢贝蕾妲小姐。现有持剑style-master-v4只保留衣装、比例、画风参照，不能直接作为新空手待机验收结果。待机双脚固定，使用自然呼吸、肩手或衣料小变化；三小只若待机露面，低幅漂浮、位置不挡脸和读数、不带攻击判定。

召唤物身体与水效独立。身体帧可为抱持/放出动作预留手掌接触点，助手层按同一世界锚点贴合。每名助手有稳定身份与状态，不随每招复制新个体；同一助手被抱持、投出、返回不能同时出现在两个位置。先小样验证接触与返回，再扩展整套动画。

## 25组动作与提示词

沿用完整25组：轻攻1/2/3、站重、蹲轻/重、空轻/重、E、Q、投技、被投、待机、前走、后退、跳跃、前冲、后撤、蹲下、站防、蹲防、受击与倒地、起身、胜利、败北。25组不是25张图；助手和特效另有各自序列。

每组提示词由“风格/身份前缀 + 逐帧动作意图 + 挂点和分层约束”组成。写清准备、出手、有效姿势、恢复；抱持写支撑手位置、放出写松手时刻。身体提示词可以不画助手，但必须对应助手参考坐标；另存助手姿势与特效提示词。不能用固定姿势、旋转缩放或重复轮廓伪造动作。

共享视角、角色高度、调色板、脚底/空中pivot。原图、SD图元及播放都要验收；拟合后保留协调的一像素深色轮廓，保护肤色与白发，对照深浅背景，不以厚描边掩盖源图差异。

## 慢慢迭代的顺序

1. 人设和官方依据 → 玩法定位 → 武器/助手选择 → 逐招设计卡。参考未核对的部分留待办，不假装定稿。
2. 统一画风的空手/持物母版与真实待机；先播放检查脚底、重心和手部。
3. 真实前走/后退，再做一个最能代表角色的攻击小样，验证助手接触、分层与判定。发现问题回到源图/设计修正。
4. 轻重、蹲空攻击 → E → Q → 配对投技与被投 → 防御受击等，逐批拟合、播放、复核动作卡。可跨角色推进14人的候选；每次生成独立保存完整提示词与待改项，不因为等一人最终验收而停下其他人的制作。
5. 集成后验证确定性与回滚、判定/中断/墙边、双人特效峰值、缓冲与池、回合开场/退出/重赛；同设备对照V3稳定版，最后用户验收再开放该角色。

记录中分别写“设计候选、源图、SD拟合、播放检查、逻辑实现、模拟器、真机、用户验收”。失败素材留历史；下一次任务读取最新进度，不复活已被替换的泛用剑招或旧Q版比例。
