# 三角色战斗交互抽样研究

日期：2026-10-13。用户要求随机获取2–3个角色，观察具体出招、特效、命中及其他战斗交互。本批采用分组随机抽样：死火的死神角色、火影角色各一位，街霸III一位；随机种子20261013，名单和抽样记录保存在`work/combat-reference-20261013/character-sample.json`。

**真机观察**：无。没有实际播放两款游戏或试听资源，不能据此声称手感、视觉效果和帧率已验证。

下文死火帧号均为资源时间轴的**绝对动画帧**，1起算，资源帧率30。跳转、循环、暂停和子动画改变执行顺序；不能把绝对帧相减直接当作完整招式实际时长，也不能直接移植成我们60Hz模拟拍。`power`是原始攻击参数，不是最终实战伤害。

## 夜一：用动作阶段开放接招，特效跟随位移

资源：[夜一SWF](https://github.com/5DPLAY-Game-Studio/BleachVsNaruto_TagAssets/blob/29dcdc2d2aa290eee2d12feb70bbc00bec0af84f/shared/assets/assets/fighter/yoruichi.swf)。主时间轴类为`yoruichi_fla.夜一全动作_2`。

初始化记录：移动速度13、跳跃参数16、重量1，防御类型1；登记三张必杀立绘、普通受击/击飞/死亡声音以及命中数据。原始值只用于比较样本结构。

### 普攻前三段

普通攻击键由`FighterKeyCtrl.attack`读取，`FighterActionLogic.attack`还要求当前动作开放攻击入口；随后`doAttack → doAction`跳转到相应帧标签。不是每按一下都不受限制地切动画。

| 阶段 | 原始帧事件 | 攻击标记与结果参数 |
|---|---|---|
| 砍1，标签399 | 399：前移12并设置阻尼1.5；408：开放砍2、普通必杀和砍技1；412：`endAct`；417：`idle` | `k1atm`存在于401–402；`k1`原始power30，水平冲量2、垂直0，普通受击时长300ms |
| 砍2，标签427 | 428：前移6、阻尼0.8；436：开放砍3、瞬步、招1、普通必杀与砍技1；441：`endAct`；447：`idle` | `k2atm`存在于431–432；`k2`power40，水平冲量4，普通受击400ms |
| 砍3，标签464 | 467：允许穿身、百分比位移、紫色残影；471：再次设置冲量；476：关闭穿身并`endAct`；478：开放砍4、招30、上必杀；485：`idle` | `k3atm`存在于469–473；`k3`power40，水平冲量4，普通受击500ms |

这些接招事件自身没有读取命中确认，属于时间轴开放动作许可。是否能组成真实连击还要看目标硬直、距离和输入时点；不能把它写成“必须打中才能接下一拳”。`endAct`在所读引擎里会清除动作入口、关闭霸体并进入FREEZE状态，`idle`才走回可行动恢复；两者不是同一个时点。

**具体启示**：角色的差异不只来自攻击图。夜一第三段把穿身、加速和残影放到同一阶段，而且在后续帧关掉穿身；这比给所有普攻统一加刀光更能表达动作逻辑。

### 砍技1：身体后撤，独立飞行物向前

该标签从743开始，对应默认下方向＋攻击的技能入口，具体来源是`FighterKeyCtrl.skill1`和当前`setSkill1`许可。

| 帧 | 动作或效果事件 |
|---|---|
| 744 | 加气5 |
| 745 | 身体水平冲量−10，允许穿身 |
| 746 | 紫色残影；`fire("kj1atm", …)`把时间轴子件转成独立飞行物 |
| 757 | 停止身体位移、关闭穿身 |
| 758 | 结束残影 |
| 763 / 769 | 结束动作入口 / 回到idle |

飞行物参数可直接读到：水平初速0、每次加速2、上限24、命中后水平速度0；竖直初速−1.4、加速0.1、上限0、命中后竖直速度0；寿命参数3、命中次数1、可被攻击的hp200。其`kj1`命中数据为power120、击飞类型。

`FighterMcCtrler.fire`取该子件和对应命中模型，发事件；`BaseFighterEventCtrl.fireBullet`建立`Bullet`并加入队伍。`Bullet`维护所属方、寿命、速度、攻击次数与被攻击状态，命中后减少次数并走命中收尾。这种效果不是一张跟随角色的背景图：角色收势后，攻击对象仍可独立继续更新。

**具体启示**：身体动作、视觉波和判定对象要分别定义。这里只确认脚本参数与对象机制，没有测量实际飞行轨迹；寿命和加速参数不能直接当作现实秒数或我们项目的每拍参数。

### 上必杀与超必杀：两种不同的“确认”

上必杀标签1081：1082转向目标，播放“夜一2”必杀立绘/暗场；1105前冲，开启紫色残影，并设置`setHitTarget("sbs1atm", "上必杀1")`。若检查框与目标身体相交，动作控制器跳到成功序列1134；若未跳转，顺序进入`上必杀MISS`1117，1118安排继续滑行并关闭当前动作入口，1124结束残影、1132回idle。

这里的`setHitTarget`是**检查框与目标身体相交后的动作分支**，并不等于已经执行了一次不可格挡的伤害。其引擎实现是`renderCheckTargetHit`，必须和真正的命中结算分开理解。

超必杀标签1334：1335播放“夜一3”演出；1385结束暗场；1388高速位移并开启残影；1398调用`justHitToPlay("cbs1", "超必杀1", true, true)`。最后一个参数允许检查防御记录，因此该门槛包括“打中或防住”，不是严格的命中限定。若没有该结果，接口走idle退出；有结果则进入1399后的追击序列，用`moveToTarget`、再次跃移、转向、下砸和残影编排后续动作。

**具体启示**：大招可以先有“是否接触”的门，再有“是否打中/防住”的门。设计与接入时要明确每个门的含义；不要用屏幕上出现特效来代替命中确认。

## 重吾：独立攻击物、落地二段与多次命中门

资源：[重吾SWF](https://github.com/5DPLAY-Game-Studio/BleachVsNaruto_TagAssets/blob/29dcdc2d2aa290eee2d12feb70bbc00bec0af84f/shared/assets/assets/fighter/juggo.swf)。主时间轴类为`juggo_fla.mc_021_2`。

初始化记录：速度9、跳跃参数14、重量6。与夜一的13/16/1相比，参数更强调重量与较慢的移动；这是源码参数比较，实际动作观感仍未播放确认。

### 普攻：攻击物与身体协作

砍1从126开始：127安排身体前移，`k1atm`存在于129–130；136开放砍2，145回idle。砍2从149开始：152调用`addAttacker("b", {applyG:false})`；153安排身体前移，同时身体的`k2atm`存在于153–155；159开放砍3，166结束动作入口，169回idle。砍3在177又生成同名子件`b`并让身体前移。

`addAttacker`把当前时间轴里的子件取出，建立有所有者、队伍和更新逻辑的`FighterAttacker`，并非单纯画一张特效。本批确认生成与生命归属路径，没有将子件`b`未经完整展开的额外伤害计入普攻总伤害。

### 下方向＋攻击：落地后开放第二段

默认`skill1`由下方向＋攻击触发。标签`砍技1`从263开始，但其中通过落地事件跳转，不能把263–329当作一条必然顺序执行的直线。

|---|---|
| 264 | 加气5；水平10、竖直−10位移；开启着色残影 |
| 268 | 设置落地跳到`sj一段`，并允许落地打断当前动作 |
| 271 | 停止动画推进并关闭霸体；这是等待外部落地恢复的节点 |
| sj一段，272 | 273震动；274停身体位移，`sjatm`存在于274–276 |
| 280 | 开放`setSkill1("sj二段")`，下一次符合技能输入可进入二段 |
| 287 / 292 / 293 | 结束动作；清除skill1/skill2入口；回idle |

第一段`sj`原始power60、普通硬直600ms；第二段`sj2`power140、击飞、破防标记为true。第二段霸体在实际攻击标记出现之前就关闭，因此不能把整招标成“全程霸体”。

**具体启示**：落地、接招窗口、霸体窗口和伤害阶段各有自己的时点。统一给整个技能挂一个“无敌/霸体”布尔值会丢掉这类交互。

### 招2：地波生成在目标处，身体不用过去

默认上方向＋技能键对应`zhao2`。标签424中，438调用`addAttacker("dilie", …)`：X轴移动到目标、偏移0；Y轴不跟目标、偏移0；不受重力。该子件对应`juggo_fla.特效地波_12`，它自己的局部帧1–2包含`zh2atm`，局部帧17有`del`标签。角色452结束动作入口，459回idle。

`zh2`原始power130、竖直冲量−5、击飞类型。地波的动作帧、判定位置和结束标签属于独立对象；没有把它的局部帧直接换算成主角色的绝对帧，也没有把X轴生成在目标处误写成持续追踪目标。

**具体启示**：范围技能可以把攻击对象生成在指定世界位置。设计时要分清“释放时锁定位置”和“后续每拍跟随”，以及视觉出现、判定出现和对象回收的时点。

## Twelve：输入表、动作标记与独立状态效果

来源为街霸III固定提交`be9b9bc69dc19822a8eca9ce3e72ba560d5a3835`。[角色动作源码](https://github.com/crowded-street/3s-decomp/blob/be9b9bc69dc19822a8eca9ce3e72ba560d5a3835/src/anniversary/sf33rd/Source/Game/plpat19.c)。

### 如何出招

运行角色18使用`pl_cmd[18] → p13_cmd`的指令表，而不是名为p18的表。`CMD_MAIN.waza_check / cmd_move`按输入历史识别，保存成功指令有效期；`PLS03`再根据资源、空地、当前状态和取消权限决定是否执行。`PLPAT.Player_attack`根据角色索引转交`pl19_extra_attack`，再按动作编号分发。

例如：`p13_cmd_46 / 49`登记动作编号17，专属表中的17对应`Att_AIRDASH`；`p13_cmd_38`登记27，表中27对应`Att_SA__D_R_A`。这是已读到的指令→动作映射。本批没有把编码方向序列完整还原成面向玩家的摇杆招式表，不能宣称核验了所有按键输入。

### 空中移动：位移表在动作事件到来时换段

`Att_AIRDASH`初始锁定出招朝向，读取动作动画表，清空旧位移，保存新位移表索引。推进时根据动画控制标记：20读取下一段位移，25追加位移，30转入跳跃物理阶段。

接触墙边并符合方向、高度等条件时，角色翻转朝向、修正位置、切到动作索引65，建立`effect_I3_init(...,4)`；该效果对象管理`bg_stop`并在条件结束后释放。这里的I3不是“一朵墙边火花”的同义词，它有背景推进状态职责。

**具体启示**：动画可以发出“换位移阶段”“反向”“落地”的控制标记，物理执行者按标记换表。镜头/背景相关对象也可能带状态职责，移植时要先辨认。

### 空中攻击与D_R_A：身体阶段和命中判定分开

`Att_AIR_A_X_E`读取动作表并处理竖直速度。在初始动作阶段等待控制标记1，切入跳跃更新；标记20读取或追加下一段位移，30切换另一份位移数据，落地进入收尾动画。函数没有直接用“播放到第几张图片”扣血。

`Att_EX__D_R_A`会依据目标所在位置与角色体型补正计算追踪冲量；`Att_SA__D_R_A`分多个阶段，标记20继续读取移动段，21停止旧位移，30按目标位置安排新阶段，64或255进入收尾。它们使用的数据表与普通动画表尚未从原游戏数据展开，因此本批不给出起手/有效/收招的精确帧数。

攻击判定仍经过`CHARSET`的当前姿态判定索引与攻击段更新，再进入`HITCHECK`队列。命中结算按目标空地、防御/Parry/受击分支设置结果、硬直、冲量、伤害和连击；`EFF02`才根据命中类型建立火花、声音和震动。攻击视觉、攻击框和命中反馈在实现上有明确分工。

### 复制变身：效果对象会改角色规则数据

`Att_METAMORPHOSE`先建立`effect_K7`，成功则播放对应动作；如果建立失败，改用备用动作索引，不假定池总有空闲。K7对象按动画控制标记推进：

1. 标记20：保存自身角色与资源身份，改成目标身份，切换基础动作数据；设置攻击、防御修正。
2. 标记30：转换并复制颜色，开启变身状态。
3. 后续检测资源结束与安全恢复状态，安排恢复动作，清空当前判定索引并重新设置判定区。
4. 恢复标记到来时恢复自身身份、基础数据与颜色，最后回收对象。另有强制恢复入口处理中断。

`K7`虽在效果文件夹里，却不是纯视觉特效。它管理玩法身份、动作资源、倍率与恢复；不能在画质降级时直接删掉它。

### 隐身：隐藏画面不等于无敌

特殊动作`Att_pl19_TOKUSHUKOUDOU`完成后调用`effect_L0_init(...,180)`。L0开始隐藏角色显示；按暂停、慢放和超必杀冻结条件处理计时；临近结束改变亮度/调色并恢复显示，特定攻击/受击/抓取状态也会触发恢复，最后回收。

本批所读L0没有关闭角色命中判定的语句。因而只能确认隐藏显示，不能把它宣称为无敌。完整实际碰撞行为仍需运行验证。

**具体启示**：效果对象至少分成纯视觉、带攻击判定、管理战斗状态三类。前者可降级，后两类的规则必须继续执行。

## 三位角色的共同命中链

死火样本的`xxxatm`子件名称，通过`FighterHitModel.getHitVOByDisplayName`映射到攻击定义ID。`FighterMC`在当前姿态找命名子件并缓存区域；`GameMainLogicCtrl`把攻击区域和目标身体区域转换到世界位置、求交集，调用目标`beHit`和攻击方`hit`。受击控制器判断可受击、防御、霸体和重复间隔，再处理伤害、硬直、冲量及效果。`hitType`选择火花/声音类别，`hurtType`区分僵直与击飞。

注意`setHitTarget`的检查子件可以只有分支功能；它不要求初始化同名伤害定义。真正的连续扣血与连段确认不能仅依据“框出现了”。

街霸样本则通过动画数据更新当前攻击编号、`att_hit_ok`与多类判定框，先把判定结果入队，再统一裁定和派发受击；命中火花由结果建立。两边都不是“角色动画碰到特效图片就扣血”。

## 对本项目最直接的借鉴

以下仅为**设计建议**：

- **逐阶段权限**：接招、穿身、霸体、落地分支分别有开始和结束事件，避免整招共用同一个开关。
- **确认结果类型**：明确区分检查框接触、实际命中、防住、霸体承受与打空；不同阶段允许的结果可以不同。
- **身体与攻击物独立**：角色后撤仍可发波，地波锁释放位置，伙伴/独立攻击物有自己的寿命与所有者。
- **特效按事件编排**：残影跟高速段、震动跟冲击段、立绘暗场跟必杀起手/阶段切换，结束时清理。
- **规则状态不可丢弃**：变身、隐身计时、锁定目标和攻击对象不应随特效池耗尽而消失；仅减少可丢弃视觉。
- **避免自动长演出**：命中、格挡和落空各有可读的收势或分支，不能所有大招都强制追着对手播完。

本批完成三位样本的静态调用链和角色资源事件追踪。未进行游戏实播、原始美术逐帧查看、声音试听、两版本配套运行、碰撞复现或我们项目接入。资料足以支持下一步对既有用户动作进行编排检查，但不替代用户动作设计，也不代表新增角色制作授权。
