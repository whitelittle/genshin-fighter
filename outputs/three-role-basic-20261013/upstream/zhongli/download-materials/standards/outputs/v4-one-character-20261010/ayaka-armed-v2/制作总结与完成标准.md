# 绫华动作制作总结与完成标准

2026-10-10。用户最新要求：先完成绫华，不进入下一人设计。当前角色测试以用户观察为主，保留整体满意的方向，不擅自重画或改招。

## 思路

制作对象是一个格斗角色，而不是一组独立好看的画。动作需先解释重心、持刀、刀路、起手/有效/回收，再决定画几张姿势。人物、握持中的刀与鞘一起设计；离手冰球、刀光等独立定位，特效范围不自动等于攻击区域。普通技体现拔刀与连斩，大招用头像切入和完整演出，但保留用户选择的简单冰球/冰风形态。

## 本轮误区与修正

|误区|固定规则|
|---|---|
|每帧按图片外框缩成一样高|统一人物解剖尺度和世界倍率；蹲、空中、倒地不按站姿外框拉伸|
|为避免裁刀而缩短刀|扩画布、保留完整刀长，重新记录ROI和根位置|
|先做空手身体，再补武器|握持动作整姿制作，手、柄、刀尖、刀鞘有连续关系|
|格挡做成向前挥刀|防御架刀、承受冲击、回位；攻击和防御刀路分开|
|拟合再叠粗描边|复用已记录调色板/方法；站防保留源轮廓，不额外膨胀|
|大招只是一个特效|头像切入→释放→对手参与主体演出→收束恢复；复杂度不等于大招感|
|用战斗帧裁切代替头像|使用项目现有头像，源图/拟合有各自版本|
|每次另建预览器|沿用雷神/草神展示模板；动作分行，默认播放|
|只拟合主角、切动作重置设置|人物、效果、头像、对手一起切换；背景/速度/显隐配置保留|
|把显示帧数当判定帧数|60Hz逻辑与关键姿势保持时间独立；命中ID和事件独立记录|

## 制作标准

1. 朝向：同一动作不突然翻面；镜像应整体作用于根、姿势、特效与判定。
2. 尺度：保持人物头、躯干、四肢比例；刀光/画布变大不能缩人物。
3. 锚点：地面脚底、空中髋轴、武器握点、对手接触点显式记录，不能靠每帧裁切居中。
4. 结构：起手/有效/收招可读；关掉特效仍看得出刀与身体在做什么。
5. 攻击：轻重、蹲空、E/Q、投技各自有用途；框不追随装饰光晕。投技上挑下砸一段，接被投再倒地。
6. 大招：必须有演出；绫华使用原冰球/冰风，头像切入，主体冲击包含对手反应，结束恢复原舞台配置。
7. 拟合：已记录绫华18色加轮廓色、预乘透明BOX、矩形painter；不新造未经比较的另一套拟合标准。对手复用游戏中的雷神矩形帧。
8. 测试交付：源图、拟合、逐姿、深/白背景、特效/对手/判定框开关齐全；切动作保留配置。由用户检查观感。
9. 状态：源图制作、拟合、网页播放、游戏逻辑、模拟器、真机、用户验收分开，不能越级宣布。

## 流程

设计动作意图 → 画完整持械关键姿势 → 提取并保留源ROI/锚点 → 统一世界尺度 → 沿既有方法拟合 → 原展示页合成人物/特效/对手 → 用户检视返修 → 导出接入数据 → 游戏内判定/分支/预算验证。

每次返修只改反馈目标。已认可的胜利、败北及其他可用姿势保留，旧源图不删除；不要因为进入下一人而把当前缺口遗漏。

- 测试包：25组、130身体姿势；八种普通攻击及E/Q均有源图/拟合和效果。站/蹲防、投技/被投已按本轮反馈修改。
- 头像：ultimate-portrait.png、ultimate-portrait-fit.png；不再裁战斗帧作切入。
- 数据：actions.json、foe-fitted.json、逐帧rects与提示词；构建顺序见攻击测试交付.md。
- 基础移动/受击及胜负存在复用帧，并非所有130姿势本轮重新生成；整体满意不能自动登记每组正式验收。
- 文件/CPU：引用与JS语法检查；矩形还原用于量化图目标，不表示无损原图或运行预算通过。
- 网页：本地播放与配置保留；用户仍可反馈可用/返修动作。
- 未完成：游戏内攻击/伤害/取消、Q命中确认与空挥/防御分支、墙边配对、回滚及运行池预算；旧训练探针尚未接这些新攻击。没有新真机验收。

当前不进入其他角色。“绫华完成”不能只看25个按钮都亮起；下一阶段必须沿本角色继续闭环，不能把本地演出叫正式角色完成。
