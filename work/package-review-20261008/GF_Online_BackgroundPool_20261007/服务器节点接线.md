# V2 双人服务器节点图

本版参考 V1/GF10 的席位分配和双向转发结构，改为 V2 专用信号。V2 是每人一个角色，选人和开战信息由两端回滚协议交换，所以不沿用 V1 三人队伍的 Team/Ready=2 条件。GF10 旧图不能直接连接本版 Lua。

`GFV2_Server_Node_Graph.json` 是完整节点和连线规格，`simulator-serverLogic.json` 是模拟器可执行规则；两者都不是官方 GIA。当前工作区保留了 V1 生成工具和接线文档，但没有官方导出的服务器节点样例及信号定义，不能凭空生成内部信号资源 ID。本包提供客户端 A GIA，服务器图按下述方案在编辑器搭建。官方导入及真机双端尚未验证。

## 挂载与变量

服务器图挂公共控制空实体，在该实体新增两个实体类型变量：`GFV2_P1`、`GFV2_P2`，不设置默认实体。所有变量读写的实体输入接“获取自身实体”，不要接监听信号的来源实体。席位从在场玩家列表分配，只服务前两位玩家；对局期间不增减第三人，也不要改变玩家列表顺序。

## 信号

| 名称 | 方向 | 参数顺序 |
|---|---|---|
| GFV2Hello | 客户端→服务端 | 无 |
| GFV2Seat | 服务端→客户端脚本 | Slot：整数 |
| GFV2Frames | 客户端→服务端 | Slot：整数、Sequence：整数、Ack：整数、Payload：字符串、Epoch：整数 |
| GFV2FramesOut | 服务端→客户端脚本 | 同上，严格保持五项顺序与类型 |

编辑器监听节点通常还有“事件来源”等原生端口，按业务参数名连线，不把原生端口算进上述五项。Lua 回调 `params[1..5]` 对应上述五项；模拟器 JSON 的参数引用从 0 开始。导入或重命名后核对真实信号名，不以节点标题代替绑定名。

## Hello 分支

1. 监听 GFV2Hello → 双分支，条件为“获取在场玩家列表 → 列表长度 ≥ 1”。
2. 真出口 → 设置 GFV2_P1：值接列表索引 **0** 的实体；实体接自身 → 发送 GFV2Seat：目标直接接该列表项，Slot 常量 **1**。
3. 此发送节点执行出口 → 第二个双分支，条件为列表长度 ≥ **2**。
4. 真出口 → 设置 GFV2_P2：值接列表索引 **1**；实体接自身 → 发送 GFV2Seat：目标接列表第二项，Slot 常量 **2**。
5. 假出口结束。每次 Hello 都允许回包，不设永久 IsInit 门槛。客户端进入握手页后每秒重试。

整数常量必须真正填写并应用：索引 0/1、席位 1/2、长度 1/2。避免 V1 曾出现的常量状态缺失导致导入全部变成 0。

## Frames 分支

1. 监听 GFV2Frames → 双分支，条件 Epoch == **1**；假出口结束。
2. 真出口 → 双分支，条件在场玩家列表长度 ≥ **2**；真出口再接 Slot == **1** 的双分支，人数不足时结束。
3. Slot1 真出口 → 发送 GFV2FramesOut，目标接读取自身变量 GFV2_P2。
4. Slot1 假出口 → 双分支，条件 Slot == **2**；真出口发送 GFV2FramesOut，目标接读取 GFV2_P1；假出口结束。
5. 两个发送节点的 Slot、Sequence、Ack、Payload、Epoch，逐项接本监听节点对应参数。Payload 原样透传，不拆分，不添加前缀，不按到达顺序过滤旧输入帧。

Epoch=1 是本版服务器通道版本，实际每局隔离用 Payload 中的 nonce、match ID 和 seq。选人阶段也通过此通道通信，**不能在服务器添加“双方已准备才转发”的门槛**，否则会卡死握手和选人。

## 游戏流程与排错

点击对战玩家时才激活通道。收到席位还不算完成握手：必须收到另一席位合法且版本相同的 V2 包，才进入选人。各自选择自己的角色；P1 选择场景；双方确认后主机只创建一次会话，另一端根据同一 roster/setup/seed 加入。VS → 图元进度条 → 对战，加载期间继续心跳。

未分配席位：检查图宿主、Hello/Seat 名称、目标玩家与整数常量。已分配但等待对手：检查另一端是否进入对战玩家页、Frames/FramesOut 五项参数类型和绑定，以及转发目标。进入战斗后按双方角色顺序、回合、时间、血量和音效检查；不能只凭 Hello 调用日志宣称服务端收到。

节点不模拟战斗，也未实现发送者身份验证；同一关卡的双人测试方案不表示可用于公开防作弊匹配。
