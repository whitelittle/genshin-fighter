# 测试反馈与整改基线

2026-10-04。用户明确纠正：问题是碰撞判定，不是要求增加攻击距离。本文件记录源码核查与整改方案，不表示修复已经交付。

## 已核查的现状

- 攻击命中函数比较双方中心的水平距离与固定高度差，没有独立攻击框和受击框。另用双方中心间距50、垂直差75作身体推挤。这两套阈值没有与当前素材轮廓校准。
- 第一批动作帧接入了表现和状态映射，未逐招接入与动作对应的碰撞框。素材中的武器、衣摆和光效不能直接当身体受击区域。
- 加载器首进及进入战斗显示黑幕，后续菜单资源请求默认不显示黑幕。创建批次上限24，解码批次上限128，另有约2毫秒预算；模拟器与真机耗时不同。
- 战斗仅有两胜标记；三个队伍格子属于选人页，没有战斗阵容栏，也没有每局各方角色败北变灰的状态记录。不能称已实现。
- 绫华比例、全体移动缺少交替步态是用户已确认的素材问题，尚未修复。

## 碰撞整改

分开身体推挤框、身体受击框、攻击框。采用脚底与角色逻辑坐标为基准的局部框，按朝向镜像；站立、蹲伏、跳跃、受击和倒地各有对应受击框。攻击只在有效帧开启，按动作关键阶段配置一个或多个框，以框相交命中，保留一次命中、无敌、防御、上下段和连击规则。投射物具有自己的位置与攻击框，不能用角色中心范围代替。

逻辑框只由模拟帧、角色状态和技能数据决定，不能从图元加载完成或动画播放回调产生。回滚恢复后须得到相同结果。身体框不含武器、头发、衣摆和特效。

先在动画工具/测试诊断中叠加三色框，按贴身、武器尖端接触、明显未接触、蹲伏、跳跃、转身和双端一致性抽样。先校准不同攻击类型的样板，再扩展。禁止以全员增加range掩盖问题。

## 加载整改

跨界面先显示全屏黑幕与真实进度，再开始解码、销毁和创建；失败信息必须可见。区分切页短等待和跨界面读条。统计解码、创建、销毁和首帧绘制的任务数及耗时后再调预算。

优先减少同页重复请求、相同素材重复解码以及短时间内销毁后重建；设受控缓存上限，保留少量可复用池，退出比赛时释放。不可把隐藏当释放，也不可一次预加载全阵容。再评估当前角色分阶段加载：先能进入战斗的基础姿势与必要攻击，后台补齐其余姿势，但未就绪动作须有明确策略，不得漏命中或切空帧。

## 阵容、动作与画风

保持固定 ROUND 1/2/3 出战、三局两胜，不擅自改回接力。战斗阵容栏各三格：当前出战高亮、待出战正常、败北者变灰；已出战且获胜者用完成/胜利标记，不能也灰成死亡。每局结果须记录各席位对应角色，平局与提前两胜单独处理，并随回滚状态与联机代次保持一致。

移动需真实交替支撑、摆腿和重心变化，不能用横移站姿代替。先制作并验收一位完整步态样板再推广；绫华按确认风格基准重做比例对照，不能只整体缩放掩盖头身比。旧素材保留。
