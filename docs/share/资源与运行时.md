# 资源与运行时

## 先定位成本

分别统计原始 PNG、压缩帧数据、静态 UI、动态图片、模板容器、可见与常驻对象、创建/销毁次数、换帧属性调用。图片矩形数不等于总控件数；一个模板容器加一个图片可能占两个控件。缩放、隐藏和池化不会自动减少常驻内存。

加载慢先检查脚本初始化、模板引用、解码、控件实例化；攻击卡顿再检查姿势切换、属性写入、排序、回滚重演。不要只凭网络 ping 或包体大小认定瓶颈。

## 素材与帧数据

保留原始图，处理图另外输出。先统一角色实际显示尺度、脚底锚点与有效颜色，再拟合矩形。帽子、耳朵、武器端点不可为凑预算强裁。头像优先完整图标等比容纳，不从身体帧顶部截取。

帧表记录尺寸、锚点、倍率、调色板、矩形与持续时间。相同帧用对象别名；代用姿势必须标为代用，不能算作新动画。

可复用压缩方案：每条矩形保存调色板索引与坐标/宽高；小坐标差和小尺寸用半字节压缩，超界走完整记录；再作 LZ token 压缩与 Base64 封装。每帧构建时解压并逐项比较原始记录。当前原型坐标为单字节，超过 255 必须升级格式或拒绝构建，不能截断。

设备展开为五字节矩形记录的二进制字符串，按需读取；避免长期为每矩形保留一个 Lua 小表。解码器的暂存数组任务完成后释放。Base64、LZ 和矩形恢复分批执行。

## 图元池与绘制

导出只存“父路径、名称前缀、池容量”的配方，复用单一图片模板创建，不在包内重复保存几千个空白控件。容量按当前演员的帧峰值规划，不按全部动作矩形之和规划。

父容器承担世界位移。换姿势时只写变化的坐标、尺寸、颜色与可见性；姿势不变则不重复写。排序只在需要时更新。回滚重演只推进逻辑，最终状态再绘制，不能在每个重演帧创建/绘制一套对象。

选人只展开当前页头像与已选展示；对战只展开当前双方演员。换场释放旧帧展开数据，销毁超过下一场需求的实例，复用仍需要的池。隐藏对象不等于销毁，清缓存也不等于已释放平台对象。

## 加载与边界

先显示静态加载层，再解码和创建。进度统计实际完成的解码、恢复、创建和销毁任务；吉祥物动画独立更新。初始化失败要留下可见错误信息。

工作量上限与时间预算同时使用，并按设备测量调整。高频选择可保留最新请求，当前小批结束后转向最新目标；双方都完成同代次资源加载后再开战。

所有压缩字符串嵌入脚本时，按需解码减少的是展开数据与实例，并非外部文件分页读取。压缩节省包体不能直接换算成帧率。原型的模拟器结果可证明状态转换，不能证明官方编辑器或手机性能。
