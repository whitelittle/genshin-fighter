# 整理版源码规则

- 2026-10-12 用户开发约定：日常开发使用未压缩、未精简源码，暂不提取新的角色共用信息；角色动作数据与专属编排各自完整保留，方便独立编辑。发布真机版时再单独处理共用提取、压缩和精简，生成独立发布产物并校验像素、元数据及逻辑一致。既有公共基础模块保持当前结构，不能将此决定理解为复制或拆散现有命中、回滚、图元池与UI系统。

本目录以认可的 V3 E 为行为基线，属于结构整理与芙宁娜候选整合。根目录隐私规则继续适用。

- 日常改 `source/`，再运行 `python runtime/tools/build.py`；`dist/` 是可重复生成的单脚本，不能只改产物。
- 保持既有 UI、60Hz 整数模拟、输入释放、双身体缓冲、分片绘制及安全边界回收。界面交互使用 `gf_ui`，不要另建组件体系。
- 菜单只负责界面与流程入口；跨场次模式状态放 `modes/`；单局模拟放 `battle/`；席位、消息和回滚放 `network/`。
- 角色编号是联机字段，新增时追加，不排序重编号。新素材接 `gf_character_registry` 与素材 provider，不运行时替换共享函数。
- 候选数据不能标成美术或真机验收。用户最新已明确纠正接入版本：芙宁娜以交付入口 `outputs/furina-design-20261010/size-review.html` 实际加载的帧图、缩放／锚点、时长、伙伴和特效为准；不能恢复旧泡泡 E／通用 Q 或只导入图片。交付只定义 Q 命中分支，落空／格挡分支属于运行适配，分别记录。
- 改动后运行 `python runtime/tests/run.py` 和 `python runtime/tests/mock_flow.py`。前者需要 lupa（Lua 5.3）、Pillow、NumPy；后者复用 `game/tests` 的离线原生控件近似器。查看桌面和手机尺寸截图。模拟器结果不等于真机。
- 不修改冻结 V3 或原图；不因整理删除历史、发布或改外部应用。未来压缩只改导出及解码边界，并证明逐像素、锚点和逻辑一致。

- 绫华最终入口为 `outputs/v4-one-character-20261010/ayaka-armed-v2/index.html`；沿其实际 `app.js`/`actions.json` 导入，不用旧基础训练探针。网页身体使用统一 `scale`，不可擅自改成尚未被网页消费的轴倍率。全25组身体、特效、Q立绘及成对root均需核验。模拟器默认从开场/标题开始、手机横屏；角色编号4和联机兼容版本4。
