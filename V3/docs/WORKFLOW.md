# V3 开发与交付工作流

1. 从 V3/client/genshin_fighter.lua 及其哈希建立分支，保持 E 稳定基线可重现。
2. 先补动作/碰撞卡，复用已有用户确认的刻晴、迪卢克概念；数值候选独立保存，不改当前正式阵容。
3. 母版、待机/步态、轻重攻击、E/Q/投技与被投逐批制作；每批先拟合成 SD 验收，保留失败样本作为研究。
4. 使用源图与成品并排、脚底线和深浅背景检查；所有补帧先人工查动作语义。
5. 集成后执行逻辑确定性、回滚一致、受击/冻结覆盖、池预算、开场、退出/重赛/重选、手机触屏与双设备联机测试。渲染缓冲不写模拟。
6. 同设备对照 E，记录 dt 分布、慢帧、写入/创建/解码量、等待/预测；诊断区分渲染与联网等待，不能只放大预测窗口掩盖问题。
7. GIA 只替换核对后的脚本，保持模板与挂载位置；使用最新脚本和模板验证实际导入。未重新打包验证的 GIA 标注历史参考。
8. 每角色通过用户验收后再推进下一角色；同时保留本次源图、工具、测试证据、hash 与决定记录。

仓库 game/ 保留 V2；V3/source 保存 E 的完整模块加载块、prefix 与 bootstrap。tools/rebuild.py 必须重组出与正式客户端字节一致的结果。旧 build_art/artlib 与 legacy-animation 工具可复用，但历史绝对路径必须移植后才运行。
