# UI 显示诊断版（2026-10-07）

用于排查：只有千星默认 3D 场景、有游戏音效，但整个 2D 游戏界面不可见。

这是诊断包，尚未确认真机故障已修复；不要当成正式发布版。

## 使用

1. 优先备份现有项目，在副本中测试。已有 A/B 界面与模板时，用附带 Lua 替换 GF_HOST 上的原 Lua，保持只挂一份游戏脚本。
2. 如果使用 GIA 导入，A 是原 A 包仅替换脚本的诊断版；B 与此前模板完全相同。已有 B 不要重复导入。不要让正式版和诊断版同时运行。
3. 保留现有图片模板索引。如果编辑器导入重新生成了 B 的资源索引，把 Lua 中 GF_IMAGE_TEMPLATE_INDEX 改为 B 的实际模板索引。
4. 正常启动后，应看到蓝底白字的 GF UI VISIBILITY PROBE 状态框，左侧还有一个红色色块。状态显示当前场景、root/view 的真实激活与可见状态、图片池数量。

## 结果判断

- 状态框、红色色块和完整游戏都出现：本次修改解决了可见性问题。再对比根节点恢复、遮罩清理和父图片不透明三项，定位必要修复。
- 状态框和红色色块出现，但游戏仍不可见：根界面可显示，继续检查内部父级、坐标和真机绘制行为。
- 状态框出现，但红色色块不出现：文本能显示，图片控件的资源/渲染路径需要继续排查。
- 两者都不出现，但有音效：需要检查更上层界面布局及祖先可见性、裁剪、位置；诊断版只主动恢复 GF_ROOT，不会强制修改其他界面祖先。

## 本次修改

- 根节点读取真实 active 状态，显式 SetVisible(true)、SetActive(true)，恢复本地缩放。
- soft(0) 首次调用不再被缓存跳过，实际关闭 mask 和 soft edge。
- 图片首次/复用显式恢复 visible。
- G.group 使用 1×1、白色、不透明图片，验证父级透明度与零尺寸影响。可能出现细小白点，这是诊断版的已知表现。
- 状态框直接挂 GF_ROOT，绕开游戏内部图片父节点，每 0.5 秒更新。

## 验证边界

GIA 的非脚本二进制记录不变；脚本提取回读一致。离线启动及进入战斗检查通过。离线渲染不能验证真机对子级透明度和裁剪的处理；正式千星客户端导入与故障修复仍待实测。
