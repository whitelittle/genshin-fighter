# 当前Demo在千星中的配置

> 2026-10-03版本提示：本文记录旧Demo导入和Input/State协议，导入层级排查仍可参考，网络部分不能直接用于现行Frames回滚版。最新文件与协议入口见[AI_START.md](AI_START.md)及[千星联机实测知识与接线](docs/千星联机实测知识与接线.md)。当前席位来自会话玩家列表，不保证对应房主身份。

按本次导出的脚本与绑定说明。真机尚未验收；官方在线API页本次读取超时，以下不冒充当前编辑器的逐按钮教程。

## 单人包

1. 新建独立测试奇域，人数设为1，导入gpt_20261002_1242_原神格斗Demo_单人AI_轻量.gia。不要和双人包叠在同一界面运行。
2. 核对客户端界面战斗根容器名称FighterDemo，挂载lua/fighter.lua。包内已有脚本和绑定，正常导入不需要重复贴代码。如果绑定没有随导入保留，只把对应包的fighter.lua挂回该容器；不要挂到图片P1或服务端节点组。
3. 确保这个界面在进入关卡后向本地玩家创建/显示且为激活状态。若导入得到的只是界面模板，需要在关卡启动流程中实例化/显示一次；使用编辑器实际导入生成的模板引用，当前Lua不负责自动创建根界面。
4. 根容器允许显示光标、接收按键，阻止按键继续传给默认角色操作。包内showCursor=true、disableKeyEventPassthrough=true；对应真机设置及实际按键响应需核对。
5. 保持子控件名称与层级，脚本通过FindChild名称查找。尤其FighterDemo下的Keqing、Diluc、Hp1、Hp2、Status、Timer、Stats；人物下Art/Sprite/P1…P2275。界面与Lua必须来自同一档位。

本版所有图片图元预先打包，Lua没有InstantiateClientUIControl模板索引、外部PNG路径或动态图元模板GUID需要手填。不要把旧动作探针的107374…模板索引照搬进来。

## 双人包：还缺服务端节点图

人数设为2，每名玩家只创建自己的一份FighterDemo界面，使用双人包绑定的lua/fighter-online.lua。该脚本已嵌入GIA；outputs/demo-online-light/fighter.lua是本地保存的同一双人源码。

重要：当前GIA只含客户端UI与Lua。server-logic.json是模拟器配置，不是千星官方节点图，不能直接导入成真机联机逻辑。下面是需要在官方服务端节点中实现的协议，节点图本身尚未交付。

| 客户端发给服务端 | 参数顺序/类型 | 服务端处理 | 发回客户端 |
|---|---|---|---|
| FighterHello | 无 | 为本局两名实际玩家建立稳定席位：房主1，另一人2 | 分别定向FighterSeat，参数：席位整数 |
| FighterJoin | 无 | 两名玩家界面完成初始化后，广播开战；重复请求不能重开已开始比赛 | 全体FighterJoined，无参数 |
| FighterInput | 席位整数、输入序号整数、事件字符串、值整数 | 校验实际发送者与席位一致；保持序号及内容。广播时不要改变参数位置 | 全体FighterInputOut，四参数同序 |
| FighterState | 快照序号整数、快照字符串 | 只接受本局席位1发送的快照，保持字符串原文 | 全体FighterStateOut，两参数同序 |

注意：上表参数顺序采用Lua侧第1、2…参数；JSON中的fromSignalParam从0开始。不要因此将参数整体错移一位。

Player1/Player2/AllPlayers是模拟器目标标签，真机需换成实际玩家实体及当前比赛玩家集合，不能把字符串当玩家实体。席位不是用户UID，不能在两台设备都写死seat=1。

服务端需要保留席位映射和双方界面就绪状态，处理重复Hello/Join，并以实际信号发送者认证输入/快照。模拟器的最简relay没有完整实现这些真机身份与重入保障，这是开发方待适配的内容。

## 需要修改的内容

| 内容 | 单人 | 双人 |
|---|---|---|
| 最大人数 | 1 | 2 |
| 根UI启动/显示 | 若导入后未自动显示，配置显示当前导入的UI | 对每个参赛玩家显示一次 |
| Lua挂载 | 检查包内已有绑定 | 检查包内已有绑定 |
| 图片/角色模板索引 | 无需在Lua中手填 | 无需在Lua中手填 |
| 服务端信号图 | 不需要 | 必须新增上表协议及玩家身份映射 |
| 手机方向 | 横屏，使用触屏布局 | 同左 |
| 按键映射 | 核验编辑器实际键位与本包期望一致 | 同左 |

PC期望：A/D/S移动和蹲下、空格跳跃、J轻攻、K重攻、L防御、R重开。源码监听KeyboardMoveLeft/Right/Backward、KeyboardJump、KeyboardCraftspersonKey19/20/21和KeyboardCharacterSkill3等事件。若真机对应实际键位不同，需要核对编辑器支持的映射或修改绑定事件；不应直接重写战斗逻辑。手机使用界面摇杆与按钮，无需映射成J/K。

## 配好后的检查

- 单人：能看到人物与UI，方向和按钮能操作，AI能接近并攻击，角色选择能交换玩家与AI角色。
- 双人一直“等待双人模式”：先查FighterSeat是否分别收到1/2，再查Join及Joined。
- 能进比赛但玩家2不能攻击：查输入是否到达服务端并转成FighterInputOut，参数类型/顺序和席位是否正确。
- 玩家1动而玩家2画面不动：查FighterState→FighterStateOut。字符串需原样传输，本版解包要求62字段，错误会打印NET_BAD_STATE。
- UI空白或Lua报找不到控件：先查根界面是否创建/激活、Lua挂载对象与层级名称、是否混用了另一档位，不先猜模板索引。

模拟器已验证双人暂停画面相同，不保证两台真机具有全局同步暂停。当前Lua用OnUpdate，若千星关卡暂停不会停OnUpdate，还需开发方为正式版加入双方共享暂停状态/门控；不能只按一侧客户端菜单暂停就宣称另一侧同帧停止。

网络信号限频、长度、时延、丢包及手机多点输入仍待真机验证。这些需要根据实测修订适配层，不是用户通过填写一个参数就能补齐。
