## 可重复构建

使用 `work/roster-v2-workflow.ps1`：默认只 build；`-Mode smoke` 构建并模拟流程；`-Mode deliver` 构建、验证后导出新时间戳包。不会下载素材、重新生图或删除文件。已有素材拟合结果是输入，改美术时先单独更新并目视核验。

主源：work/build-roster-v2.mjs（UI/角色/打包）、v2-menu.lua（菜单/回合）、v2-pack.mjs 与 v2-unpack.lua（编解码）、v2-loading.lua（资源门槛）。加载生成器依赖 work/build-duel-loading.mjs 与 duel-loading-prefix.lua。修改生成 Lua 后重建会覆盖它，应改上述源文件。

模拟验证：verify-roster-v2.mjs、verify-roster-v2-mobile.mjs；战斗规则变更另运行 verify-vnext-combat.mjs。三个检查分别覆盖流程、视口、战斗，不冒充官方编辑器测试。

导出器 work/deliver-roster-v2.mjs 分开服务器 A 与客户端 B，检查 A 兼容性和脚本往返一致；客户端 B 保留外层模板列表结构。不能把两者混为官方节点包。节点文件尚待用户提供导出样本。

## 取用规则

有效资产必须满足“当前构建实际引用、来源可追溯、拟合/解码校验通过”至少相应的用途条件。旧包、早期素材与录像保留对照，不能直接当作当前实现。分享技术方法时使用 docs/share，避免连同个人绝对路径、角色设计或原始参考资源打包。外部素材再分发权限需另核验。
