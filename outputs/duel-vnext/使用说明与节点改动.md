# 双人下一版候选：动作与菜单

2026-10-03。这是可检查、可导入的候选版本，**模拟器通过；千星真机导入、手机帧率和本轮新信号未验证**。旧版与原素材保留，本轮未修改官方编辑器、游戏关卡或个人资料。

## 文件与导入

- `原神格斗_双人下一版候选.gia`：独立客户端模板 `FighterDuelNext`，内部挂脚本节点仍是 `FighterDemo`。
- `fighter_duel_vnext.lua`：与包内 `lua/fighter_duel_vnext.lua` 相同的 ASCII/LF 源码，无 BOM。不要拿本文件单独覆盖旧版 UI：新控件、池容量和信号协议都变了。
- `fighter.save.json`：本地模拟器工程；`server-logic.json`：本地模拟器中继配置，**不是官方节点图**，不含在 GIA 中。
- `verification.json`、`combat-verification.json`、`flow-verification.json`：三组模拟器检查。
- `01-start.png` 至 `06-result.png`、`mobile-*.png`：实际模拟器截图。

导入为独立模板，每个参赛玩家仅显示一份 UI，使用导入后实际生成的引用。保留包内控件名和层级，脚本挂在 `FighterDemo`，不要挂单个像素控件。不需要在 Lua 中手填导出 GUID 或动态模板索引。包体约 9.5 MB，实际编号、控件数以 `build.json` 为准。

## 本轮行为

开始 → 选人 → 双方确认 → ROUND ONE/FIGHT → 对战 → 回合结束 → 下一回合 → 两胜结算。头像下选人，上方两人站立预览，P1 选场景；更换场景使双方重新准备。拿到 Seat 不自动 Join。再战保留所选角色并请求对方确认；重新选人和返回开始也会停止旧会话。

角色总关键姿势：刻晴 18、迪卢克 22，含原来的四姿势。本轮新增 32 姿势，补移动、蹲伏、蹲防、站防、受击、浮空、倒地、起身、跳跃、下段和技能姿势。**这仍是关键姿势动画，不是已经补齐逐帧中间动作的完整版。**刻晴待机用轻微呼吸位移；迪卢克另有第二待机姿势。刻晴 Q 蓄力暂复用站防姿势。

- S/摇杆下：蹲伏；下+防御：蹲防。下+轻攻：下段；前+重攻：上段；普通重攻：中段。空中攻击按上段防御，空中不能防御。
- E 按钮/236+J或K：刻晴首次投雷楔，标记保留约三秒，再次输入瞬移斩；标记本身本轮不造成伤害。迪卢克按三次输入接三段 E，末段倒地，不自动完整三段。
- Q 按钮/236236+K：消耗 100 能量。刻晴多个方向斩光只判一次命中；迪卢克火鸟有向前飞行的判定距离。E、Q 数值是本项目格斗改编，不是原作参数。
- 623+K：保留挑飞。浮空 → 落地倒地 → 起身保护；追击上限五次，保留伤害缩放。
- 回合中不能通过旧角色、地图、重开输入直接重置比赛；重赛走结算与准备流程。诊断按钮默认收起，点击显示网络统计。

## 官方节点最小改动

沿用已经实机走通的稳定 P1/P2 实体映射。列表下标为 0/1；Lua 回调参数为 1 开始。1077936129 是用户项目的公共实体 GUID，不是固定玩家索引。公共变量的读写必须指向同一实体；不要混用部分自身实体、部分公共实体。

|客户端到服务端|参数顺序与类型|服务端发送给两名玩家|
|---|---|---|
|FighterHello|无|向 P1 发 FighterSeat(1)，向 P2 发 FighterSeat(2)|
|FighterSelect|Slot整数、Role整数、Ready整数、Stage整数、Epoch整数、Revision整数|FighterSelectOut，同序六参数，原样转发|
|FighterJoin|无|FighterJoined，无参数；保留可重试回包|
|FighterFrames|Slot整数、FirstFrame整数、AckFrame整数、Payload字符串、Epoch整数|FighterFramesOut，同序五参数，原样转发|

**最容易漏的变化是 Frames 新增第 5 个 Epoch。旧节点只发四参数时，本版会一直拒收输入。**FighterSeat/FighterJoined 不要误加 Slot 到 Joined。信号名、参数名、类型两边严格一致。

`FighterSelect` 新监听链可以先直接向 P1/P2 各发送一次 `FighterSelectOut`，六个输入端口逐项连到六个输出参数。Role：1 刻晴、2 迪卢克；Ready：0 未准备、1 已准备；Stage：1/2/3。Epoch 是比赛代次，Revision 是该玩家选择状态的版本号，不能把它们改成常量。重复包允许，客户端过滤旧版本。所有 UI 实例都监听回包，但只改自己的选择并发送自己的确认。

开战门槛在客户端为同一代次的双方准备；P2 仅满足门槛后请求 Join，两端收到 Joined 且准备齐全才建立回滚会话。真机中继若还使用 `IsInit/Started=false` 作为一次性回包门槛，需要取消这个门槛，否则重赛无法再次收到 Joined。可以保留 Started 用于 Frames 转发，但每次新的准备流程必须仍能回包。

本候选模拟器中继未增加可信 Sender 认证。正式竞技版还需在服务端核验发送者与席位，并权威记录准备与会话；事件源/信号来源哪个端口对应真实玩家，必须实测后再绑定，不能凭名字锁死。旧包隔离目前覆盖 Frames，不等于断线重连和恶意包处理已经完成。

## 运行成本与边界

人物每个席位共用峰值 2335 图元池，两个席位可选任意角色，总计 4670；没有给每个姿势各建一套池。每席位火鸟峰值 338，头像峰值 380；三背景共用峰值 2486 的池，只在地图改变时重写。人物沿用节点缓存与差量属性更新，回滚重算只在最终绘制一次。

总常驻图片约 9600，明显高于旧版四姿势/方块背景基线：新增负载主要来自背景、头像及火鸟，而不是把四十个姿势全部预加载为四十套控件。隐藏不等于释放。本版本不能据模拟器速度承诺手机性能，下一次真机应分别记录菜单、移动、连续攻击、双 Q、倒地和换场景的 LuaHz/网络推进/暂停预测。未实现跨姿势图元匹配或异步预加载。

同角色目前以 P1/P2 标签、头像边框与血条颜色区分，服装替代配色尚未制作。AI、三人接力、入场和胜利演出均留后续。

## 复现构建

依次运行 `python work/vnext-assets.py`、`node work/vnext-fit.mjs`、`node work/build-vnext.mjs`。Node 使用工作区依赖运行时或本机 Node；拟合引擎引用已安装的本地像素工具。生成图源文件必须先存在，构建不会再次调用 ImageGen。

验证命令：`node work/verify-vnext.mjs`、`node work/verify-vnext-combat.mjs`、`node work/verify-vnext-flow.mjs`。修改生成 Lua 后重新构建会被覆盖，应修改 `build-vnext.mjs` 或 `vnext-menu.lua`。
