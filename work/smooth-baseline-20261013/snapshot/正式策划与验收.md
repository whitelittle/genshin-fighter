# 原神平面格斗：正式需求与实现基线

> 2026-10-03更新：本文保留长期需求与早期实现描述。当前UI/AI本轮范围见[下一版本UI与AI方案](docs/下一版本UI与AI方案.md)，当前网络已改为Lua输入回滚，不能沿用本文早期P1权威快照实现状态。用户取消本轮三人接力；当前仍单角色三局两胜。

更新：2026-10-02。用户本轮完整说明为最高优先级；以下策划数值是首轮实现建议，后续按试玩调平衡。

## 确定范围

2D横版平面1对1格斗，千星为目标平台，PC键盘及手机摇杆/按钮。仅刻晴（单手剑、雷）与迪卢克（双手大剑、火，武器明确指定狼的末路）。原作默认服装、非Q版、半侧身。最多两名联机玩家；单人有角色专属AI。单人版与双人版保持两个独立交付文件，不混成一个自动切换模式的文件。

UI、战斗画面的构图和动作节奏参考DNF Duel，必要时参考其他格斗游戏。用户决定尽量接近DNF Duel并保留逐级降清晰度方案：保存高质量母版，按分辨率/色数/特效/画帧采样导出多档千星运行资源，以双设备真实负载测量定最终档位。详见美术分级与性能验收.md；不固定为低清像素风，也不未经测量直接全量高清拟合。

## 动作参考的准确对象

DNF Duel使用具体转职角色，不是一个统一的男女鬼剑士角色。先按武器和目标动作将参考映射为：

- 刻晴：Spectre（刃影）的敏捷斩击、收刀/重心转换与连招节奏；Ghostblade（剑影）的剑路与突进构图作辅助。刻晴仍使用单手剑，不照搬刃影的双武器持握或剑影的鬼魂伙伴。
- 迪卢克：Berserker（狂战士）的重量感、蓄势、纵劈和上挑作主要动作参考；改为迪卢克双手大剑与火焰，不照搬血气特效及单手持剑方式。

官方参考入口：[角色名单](https://dd.nexon.com/en/fighters)、[刃影](https://dd.nexon.com/en/fighters/4)、[狂战士](https://dd.nexon.com/en/fighters/5)、[剑影](https://dd.nexon.com/en/fighters/16)、[系统](https://dd.nexon.com/en/system/move)、[官方刃影实战视频](https://www.youtube.com/watch?v=NctPeViOBt8)。当前已核对页面身份与参考入口；尚未完成视频逐招截图和关键姿势分析，不能把这些链接算成已完成动作参考图。

每招参考卡记录：来源与时间点、蓄势/命中/收招关键姿势、脚底与重心、肩/肘/腕和武器轨迹、前后手关系、目标高度、取消点，再适配角色造型。参考动作与最终人物动画分开归档。

## 操作与共同规则

| 操作 | PC首版 | 手机首版 |
| --- | --- | --- |
| 左右移动/蹲下 | A/D/S | 左侧八方向摇杆 |
| 跳跃 | 空格，后续可加W | 跳跃按钮，摇杆上方向可设为跳跃 |
| 轻击/重击/防御 | J/K/L | 轻击/重击/防御按钮 |
| 下段/蹲防 | S+J / S+L | 摇杆下+轻击 / 下+防御 |
| 上段 | 前+K，空中攻击按招式表 | 摇杆前+重击 |
| 必杀/挑飞 | 236+J/K / 623+K | 摇杆方向序列+攻击按钮 |
| 超必杀 | 236236+K，满能量 | 同一搓招+重击，不设一键超必杀 |

方向相对角色朝向，换边后反转。前摇、有效期、后摇、命中停顿、受击硬直、取消窗口按统一战斗模拟步计时；美术帧持续时间映射到这些状态。输入必须支持按下、持续、松开、斜方向和中立，攻击按键只按新的按下沿发招。

当前原型K是直接上段重击；正式版计划将中段普通重击与前+K上段区分，需要同步调整招式、AI和动画，不能只改操作说明。

站防挡中段和上段，蹲防挡中段和下段；空中防御首版不开放。必杀必须搓招识别，手机也不变成一键技能。超必杀有资源条件，指令优先级高于短指令。

保留真实连续命中计数、伤害递减、挑飞/空中追击、倒地与起身保护。主动跳跃和浮空受击使用独立状态。扩展招式后逐招配置追击消耗和伤害递减，不将所有招式一概无限托起。

首版正式规则建议100生命、60秒回合、先赢2回合胜；平局不加分。角色选择后固定对局，角色、场景、难度、重赛均由菜单选择并在联机开局前同步。

## 角色打法与招式设计

刻晴：近中距离机动、快速单手剑、突进确认、升斩追击。动作短促，快速收剑；AI偏重距离调整、空挥惩罚、轻击确认、及时蹲防和撤退，不无条件抢招。

迪卢克：中距离大剑压制、明显蓄势、纵劈、升斩、火焰斩。AI偏重利用剑长、对空、抓收招、上/下段混合与资源择机使用。两者必须有不同策略参数和动作决策，不只是速度/伤害不同。

首版双方共同动作：待机、前进、后退、蹲、跳、地面轻/重、前重上段、蹲下段、空中轻/重、站/蹲防、地面/空中受击、倒地、起身、胜负姿态。

角色技能候选：刻晴236突进斩、623雷光升斩、214后撤雷斩、236236天街巡游；迪卢克236火焰重斩、623烈焰升斩、214逆焰蓄斩、236236黎明。这些是策划候选，尚未全部实现；不能把简单改名视为多段演出或新技能已完成。

首轮超必杀机制可先单次命中验证资源、指令、取消和网络同步，之后替换为人物专属多段动画/判定。需要连段衔接时先验战斗规则，再定美术关键帧。

## 手机专项

左侧摇杆提供八方向，中心死区与方向切换阈值防抖；松手回中，触点丢失清除持续输入。右侧按钮需要与左侧摇杆同时操作，跨按钮滑动/松开不能留下按住状态。UI用手机安全区和不同宽高比布局，不能把PC按钮整排缩小移过去。

首要技术风险：当前模拟器源码的指针通路与真机多点触控事件需要逐项核对。单鼠标能拖摇杆并不证明手机能一边搓方向一边按攻击；在相关验证完成前，手机状态标记为未通过。

## 三个正式场景

1. 风起地大树前：首个完整制作场景。前景地面清晰、大树与草地在后景，树冠与风动点缀不遮挡角色。
2. 蒙德城大桥/城门口：采用大桥临近城门的平直对战段，桥面是战斗地面，城门、风车与水面分层。
3. 风龙废墟外围：采用外围平整残垣区域，破损石柱和远处废墟建立纵深，避免以高对比裂纹遮住剑路。

每个场景统一地面原点、战斗宽度和角色显示比例。美术可以有纵深，战斗只有一个平面，不加入可行走深度。场景选择必须同步，避免双方分别随机。

## 美术、UI、声音

先确认两张完整持械静态母版及实际场景尺度，再做“待机→轻击→升斩→浮空受击→倒地→起身”小循环。参考图、正式画帧、动画工程、千星矩形数据和运行接入分别留存。逐帧拟合、固定锚点、共享图元池，不把整套动画展开为常驻隐藏控件。

UI参考DNF Duel的信息层级：双侧头像/生命条/资源条，中间计时和回合标记，侧边连击，醒目的命中和防御反馈。界面、姓名、招式、胜负和操作说明使用中文。最终UI与场景不等同于当前调试按钮与石柱背景。

完整成品还包括菜单、角色/场景选择、单人难度、招式表、暂停、重赛/返回、音量，以及挥剑、命中、防御、雷/火、起跳/落地、KO和背景音乐。素材未取得时可保留明确占位，不标记美术/音频完成。

## 联机边界与验收

继续保留两个独立文件。双人版当前是玩家1主持战斗、服务器转发、玩家2接收完整状态；模拟器零延迟时已验证双方暂停画面一致。正式扩展中的新招式进度、能量、场景、选角、演出和随机决策必须全部同步。

后续验证两端实际网络延迟、消息乱序/重复、断线清空持续输入、重赛和身份绑定。没有完成状态保存/恢复与输入重演前不宣称实现回滚；模拟器serverLogic JSON不是千星官方节点图，真机必须制作配套服务端节点。

## 开发顺序和完成条件

1. 需求与参考：本文、招式/动作参考卡、资产清单、双平台输入规范。
2. 战斗：资源与超必杀、上/下段组合、角色选择与两种AI、联机同步回归。
3. 操作：八向摇杆、右侧按钮、同时触控、宽高比/安全区、设备切换。
4. 美术：两角色母版、小循环、完整动作和雷火特效；风起地优先，再补其余两场景。
5. 成品：完整菜单/UI/声音、两份独立工程、GIA与服务端节点说明、PC/手机模拟器及真机验证。

每项明确记录未开始/进行中/模拟器通过/真机通过。只有两个角色完整可选、PC与手机操作可用、角色AI可玩、全部规定机制和三场景接入、联机配套及验证交付后，才将整个游戏标记完成。
