# 第一版测试候选：节点图接线

本地 `server-logic.json` **只用于模拟器**，GIA 没有把它变成官方节点图。下面需要在千星编辑器接线。本版新增选人、退出与开战轮次参数，不能继续沿用无选人复测包的旧参数表。

## 挂载与变量归属

推荐把服务端中转节点图挂在一个固定控制实体（沿用 `1077936129` 可），`P1`、`P2`、准备状态、场景和 Epoch 都保存在该实体。此图中的“获取自身实体”指控制实体，**不是玩家**。所有获取/设置自定义变量均指向同一个控制实体，避免之前“玩家图自身”和“固定实体变量”混用。

在场玩家列表本项目实测为从 **0** 开始：第 0 项 P1，第 1 项 P2。长度不足 2 时不取第 1 项。已收到用户真机实体 `[3,5]` 的截图，3/5 是实体引用，1077936129 是查询用的 GUID，不能把三者当作同一种数字互换。

## 信号参数（顺序必须一致）

|客户端→服务端|参数|服务端→客户端|参数|
|---|---|---|---|
|FighterHello|无|FighterSeat|Slot（整数 1/2）|
|FighterSelect|Slot、Role、Ready、Stage、Epoch、Revision（六个整数）|FighterSelectOut|原样六参数|
|FighterJoin|Epoch（整数）|FighterJoined|同一 Epoch（整数）|
|FighterFrames|Slot、FirstFrame、AckFrame（整数）、Payload（字符串）、Epoch（整数）|FighterFramesOut|原样五参数|
|FighterFlow|Slot、Action、Epoch、Revision（四个整数）|FighterFlowOut|原样四参数|

Role：1 刻晴，2 迪卢克，3 凯亚，4 琴，5 可莉，6 丽莎，7 甘雨，8 烟绯，9 魈，10 胡桃，11 岩盔丘丘王。

Ready：0 未准备，1 已确认/正在加载，2 加载完成，3 返回开始界面。Stage：1 风起地，2 蒙德大桥，3 风龙废墟。Action：1 请求再战，2 重新选人，3 返回开始/退出当前对战。

**FighterJoined 现在必须带 Epoch。** 旧的无参数回包会被完整版本拒绝。无选人复测包仍使用其独立说明中的旧协议。

## 分支 A：席位

`监听 FighterHello → 获取在场玩家实体列表 → 长度≥2 → 第0/第1项 → 保存 P1/P2 → 分别向 P1/P2 发送 FighterSeat(Slot=1/2)`。

可连续向不同玩家发两次，这种结构已在用户此前真机成功。发送对象直接接玩家实体列表对应值；先不要通过尚未确认写入的变量兜一圈。

## 分支 B：选人和加载

`监听 FighterSelect → 校验 Slot/Role/Ready/Stage → 校验实际信号来源对应 P1/P2 → 保存该席位最新快照 → 分别向 P1/P2 发送 FighterSelectOut(六参数)`。

每个席位保存 Revision，较小/相等版本忽略；新 Epoch 清除上一轮准备/加载状态，旧 Epoch 忽略。P1 决定场景。客户端每秒重发最新快照，用于弥补选人包遗漏。

将“信号来源实体”接入打印核验，确认它在当前编辑器中确实表示发信玩家后再做身份比较；不要未经观察就把“事件源实体”“自身实体”当作玩家。模拟器是全员中转，官方图应补上来源校验。

## 分支 C：开战

`监听 FighterJoin(Epoch) → 两玩家存在 → Epoch 与保存快照一致 → 两席位 Ready 均为2 → 向 P1/P2 发送 FighterJoined(Epoch)`。

重复请求可重发同一 Epoch 的回包。客户端忽略重复开战。仅人数满 2 或 Ready=1 都不能开战，否则手机仍在创建图元时 PC 已经推进战斗。

## 分支 D：战斗输入

`监听 FighterFrames → 校验 Slot/来源/Epoch → Slot=1 发给 P2；Slot=2 发给 P1 → FighterFramesOut(Slot,FirstFrame,AckFrame,Payload,Epoch)`。

FirstFrame、AckFrame 不能接反；Payload 必须是字符串。不要自行解析、改写或加前缀。无按键时也有空输入和 ACK 包，不能把“玩家没动”当成不用转发。不要按 Started 永久挡住后续会话；门槛应随 Epoch 重置。

## 分支 E：结算、再战和退出

`监听 FighterFlow → 校验 Slot/来源/Epoch → 原样向两玩家转发 FighterFlowOut`。

Action=1 是一方投票，客户端每秒重发等待中的投票，双方都投票才开始新 Epoch；客户端保留同角色池。Action=2/3 表示离开当前比赛，另一端也停止战斗并释放战斗实例。Ready=3 的快照同时记录返回开始的状态，避免退出包和新 Epoch 快照先后顺序不同导致双方落到不同页面。

本版“退出”指返回游戏的开始界面，不是关闭原神进程。掉线自动裁定胜负、账号重连恢复不在当前已验证范围。

## 测试与打印

一次打印一整条：`信号名 / 发信实体 / Slot / Role或Action / Ready / Stage / Epoch / Revision / 目标P1 / 目标P2`。战斗帧打印做抽样，避免每帧字符串打印干扰手机性能。

先跑无选人复测确认 Hello/Joined/Frames，再接本页完整协议。验证双方不同角色、同角色、只一方准备、手机晚加载、结算单方再战、双方再战、退出后再次进入。加载时应有百分比；卡在加载完成但不开战，优先检查 Ready=2 和 FighterJoined 的 Epoch 接线。
