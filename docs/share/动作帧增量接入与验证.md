# 动作帧增量接入与验证

通用技术记录，2026-10-04。设计规范、模拟器证据、真机证据与推断应分开存放。

## 可重复生产链

1. 固定角色母版、摄像机与比例，明确每格动作顺序；源图版本化保存，不覆写认可母版。
2. 检查透明度、主体数量、画布裁边和附件归属。连通域数量不能直接等于角色数量：武器可能与手部因透明像素断开，需目视确认后将邻近附件纳入主体裁切范围，不能为通过检查直接删除。
3. 记录脚底锚点与角色身体尺度，避免用伸长的武器计算角色身高。先降到实际显示网格，再限色、拟合非重叠矩形；报告拟合数量与重叠，不称数学最小解。
4. 帧ID和状态映射独立于角色ID；保持时长与姿势数量独立。动画按确定性逻辑帧选图，命中事件不能等待图片绘制完成。
5. 给弃用源图建立可机器读取清单，构建时禁止导入。保留历史资产供追溯，清理需另行授权。
6. 先做源帧/锚点/状态映射检查，再抽样测试开始、准备、回合切换、结算与资源退出。包生成后本地反向导入和格式校验，仍需目标编辑器导入与实机验证。

## 存储与运行成本

静态模板不展开全部动画图元，存帧矩形数据及共享池容量配方。不同帧复用角色池，当前场只实例化当前角色；菜单按页加载头像。换场明确销毁不再需要的实例，并清除解码后的帧数据。隐藏不会释放内存。

图片数、模板容器数、文本数、总控件数分别统计。双角色同帧池仍是两个实例；尺寸倍率不会降低图元数量。压缩文件大小只表示存储/传输，不直接表示运行内存。

加载采用实际完成/总任务计数，建立、销毁、解码均计入。初始化错误应显示诊断；批量大小和时间预算须按同设备测量调整。避免在每帧扫描整棵控件树。属性差量更新只降低写入次数，不能承诺没有卡顿。

## 双端菜单一致性

席位与玩家实体引用独立；列表序号不等于业务席位编号。以代次过滤旧回合、以版本号过滤旧快照；相同版本重发允许补包。双方当前代次资源准备完成后开战。静止玩家也持续确认输入。

结果页面返回菜单需要广播双方，增加代次并清空旧输入/准备状态；不能留下永久开始标记阻止下一场。模拟器服务器逻辑不能冒充目标编辑器的节点图资产。
