# 三人阵容版：存储与素材修订

同日后续修订：游戏文字统一 ROUND 1、ROUND 2、ROUND 3；选人卡片、栏位、展示框及操作底板采用圆角组合，静态控件由 829 增至 991，动态池配方数量不变。最新设计以 docs/当前设计基线.md 为准，可分享方法见 docs/share；最终包体和文件以新 delivery.json 为准。下文 R 场简称仅为早期技术记录，不表示当前游戏标签。

更新：2026-10-03。最新用户要求 45 位可玩角色、双方各选 R1/R2/R3、头像分页、场景随机、恢复关键地标、交付 GIA 及两份安装说明。若娜瓦经用户后续说明暂不制作；本轮不再沿用此前“不做三人”的旧范围。

## 已实现的存储结构

1. **原始素材与设备数据分开**：原始官方参考和生成 PNG 留在 assets/roster-v2，GIA 不附带原始 PNG。源文件、旧包全部保留。
2. **行记录压缩**：一条矩形通常用坐标差分、宽高半字节、调色板索引表示；遇到大矩形或大坐标跳跃，使用完整记录，不丢坐标精度。随后作 LZ token 压缩和 Base64 编码，设备 Lua 可解码，不依赖外部 zlib。
3. **重复姿势引用**：完全相同的姿势共享同一个帧对象，代用状态不复制数据。本版 344 个帧项采用别名引用。
4. **池配方**：模板不存 P1…P6000 这样的空白图片定义，也不在 loadingJobs 重复记录每个空白图片的位置和颜色；只保存路径、名称前缀和数量。运行时复用一个 B 模板创建。
5. **展开格式**：已展开姿势仍是每矩形 5 字节的二进制字符串。绘制时读坐标和调色板索引，不长期保存每条矩形一个 Lua 小表。变换/颜色差量缓存仅为当前演员维护。
6. **分场调度**：菜单只展开当前页 10 个小头像，以及选择后两张展示头像；不创建全部站立角色。战斗只展开当前 R 场两个角色。R2/R3 黑屏释放上一场数据和多余实例，再加载下一场；退出释放战斗池。改变页面时释放离页头像展开串和多余实例。
7. **真实进度**：Base64 分块、LZ token 分批、行记录还原、创建和销毁均计入任务，派蒙动画独立更新。2 ms 是候选工作预算，不是手机帧率保证。

## 数字与边界

45 位角色，646 个唯一帧对象（含头像）对应 5,790,195 字节完整五字节矩形记录。旧十六进制表示需约 11,580,390 字符；新压缩 Base64 数据约 4,093,868 字符，减少约 **64.6%**。Lua 约 4.5 MB，GIA 约 5.2 MB，以最新 storage-report.json / delivery.json 为准。

【构建测量】以上是同一批素材的表示方式对照，不是把旧 11 角色包与新 45 角色包直接比较。PNG 总大小不等于 GIA 数据量，也不等于 GPU 或控件内存。

初始页动态图片数以 storage-report.json 为准；库中所有角色的共享峰值定义总量不代表它们同时常驻。模板容器和 Pixel 图片通常每图元两个控件，另有 UI/文本/原生场景；不能把图片数当作总控件数。

高细节新角色的单演员峰值仍可能超过旧角色；当前最高约 6,224 张图片。本版降低存储和常驻范围，并没有承诺消除所有攻击换帧卡顿。后续可继续按真机反馈优化 Q 特效、图元拟合及属性调用，不能以削掉脸部/头饰的方式硬凑上限。

## 素材修订

头像改用完整官方角色图标，等比容纳头饰、耳朵、头发，取消旧的身体帧顶部裁切；小头像 32×32、展示/战斗头像 48×48。像素缩放保持像素边缘，不做额外模糊。界面每页 10 个头像，左右三栏位以名字和 R 序号引导。

岩盔丘丘王依据 [参考图](https://www.zerochan.net/3369089) 重做长臂、短腿、白色双角面具和岩甲轮廓。新增 34 位角色加丘丘王修订，共 35 张关键姿势表，使用内置 image_gen；路径及提示规格在 assets/roster-v2/generation-manifest.json。头像来源、身体参考链接见 official-source-records.json；技能名称/说明核对用的 [genshin-db 提取资料](https://github.com/theBowja/genshin-db) 属社区数据，不能冒充官方设计确认。

近期角色另参考了原神团队发表于 PlayStation Blog 的 [尼可介绍](https://blog.playstation.com/2026/05/11/20260511-gi/)、[菲林斯版本介绍](https://blog.playstation.com/?p=409125)、[丝柯克版本介绍](https://blog.playstation.com/?p=405852)。角色实际技能的复杂后台机制在本项目简化，不把代用动画称为全部动作完成。

## 证据分级

【用户真机观察】上一包头像裁切/降采样严重、丘丘王不像、读条慢、地标丢失。本次修订针对这些观察。

【模拟器验证】抽样角色、三场换人/加载屏障、结算投票/再战/退出、19.5:9 与 4:3 选人界面，以及原有回滚战斗检查。

【待验证推断】压缩数据和减少展开小表预期能降低加载与 GC 压力；具体手机收益尚未测量。当前没有官方编辑器导入或真机帧率证明。
