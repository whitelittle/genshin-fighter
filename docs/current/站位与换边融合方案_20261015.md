# 站位与换边融合方案

2026-10-15。用户要求查看源码，分析如何融合前述街霸/拳皇式站位与换边。本文是源码核验及设计建议，没有修改游戏规则、构建或试玩服务。用户已明确防御课不教学换边，换边后面单独教学。

## 建议的统一规则

以现有自动朝向、后方向防御、前冲/后撤为基础，先修好跳跃换边。拳皇式滚动穿越如以后采用，应作为明确的独立动作，不直接把普通冲刺改成无敌穿人。

|操作|身体能否通过|朝向与防御|
|---|---|---|
|走路、普通前冲|地面互相阻挡|自由行动时朝向对手|
|后撤|保留现有移动和短暂无敌；仍受身体阻挡|保持本次后撤朝向，结束后再检查|
|前跳|高度和距离足够时允许越过|起跳锁定空中朝向；落地恢复结束进入中立后再朝向对手|
|攻击、受击、格挡硬直|依各动作的身体规则|保留动作朝向；防御受理方向仍按实际攻击方位置判断|
|明确允许穿越的技能|仅指定时段可穿越|招式规定何时转身；不能每拍追踪转向|
|换位投技|仅该投技明确设置时换位|根轨迹、双方位置与朝向同步处理|

人物在地面中立、对手跳到另一侧时，可以先转身；正在跳跃的一方可以继续保留起跳朝向，落地后再转。两人的转身时刻可以不同。A/D始终是屏幕左/右，前/后是相对朝向的解释，不新增转身按键。

## 内存参数探针：不是正式修改

以已运行v7构建为输入，仅在Lua内存副本替换碰撞高度。旅行者与丘丘王间距180设计单位，前5拍输入前跳后松开，观察90拍；左右方向各测一次。

|身体阻挡高度候选|左右两方向结果|跳跃最高点|
|---|---|---|
|220（当前）|均不能越过|238.5|
|180 / 160 / 140|仍均不能越过|238.5|
|120 / 100|均能越过，结束后双方朝向相反且正确面对彼此|238.5|

证据在 `outputs/movement-integration-analysis-20261015/probe.json`。这说明单纯“已有自动转身”无法解决碰撞阻挡；也说明可以先保持跳跃轨迹，在身体推挤层取得换边能力。**120只是这一距离、这一组角色的可行探针，不是已确定的全角色参数。** 尚未核验更多距离、双人空中相遇、墙角和招式碰撞，不能直接全局替换数值交付。

正式方案应把身体推挤盒作为确定性的玩法数据，与美术像素尺寸和攻击/受击盒分别处理。每拍只做固定数量的矩形和状态比较，不遍历图片矩形或按图像透明轮廓计算碰撞；无需新增角色画面控件。

## 必须一起处理的三个边界

1. **方向输入缓存。** 当前236指令用“现在的face”解释过去的原始方向，双击冲刺也保留`lastFwd/lastBack`时间。翻面后旧记录可能被重新解释。基础方案建议在自动转身时切断旧方向指令序列、重置前后双击缓存，保留实体按键按住/释放状态。先选一致规则，再考虑跨换边缓冲的进阶技巧。
2. **防御朝向与击退。** 受理防御已依据攻击方位置，但格挡击退仍用`-d.face`。角色朝向锁定而攻击方换侧时，可能出现防对方向却向错误方向被推的情况。应按实际攻击方/接触方向计算击退，并加入两侧检查。
3. **复制和联机校验。** 已验证只翻转一个角色face而不改其他状态，当前`hash`不变。复制本身会保留face，但简化hash发现不了这种差异。新增身体穿越标记、转身状态或方向缓存后，也必须加入快照与校验；有新协议行为时独立候选隔离旧客户端。

无敌控制“能不能受伤”，身体穿越控制“能不能通过”，允许被投与否另行明确。不能用同一个无敌字段隐式决定所有行为，也不能由动画播放到哪张图决定碰撞。

## 实施顺序与验收

第一批只做跳跃、推挤和转身节点的独立候选，地面走/冲仍阻挡；不改当前防御课。验证左右对称、多个起跳距离、大小体型、墙角、落在对手头上、对手同时移动/跳跃、出招朝向锁定。

第二批补朝向校验与方向缓存规则，核对换边后的前后移动、站防/蹲防、格挡击退和输入指令。进行完整状态复制/回放及延迟丢包回滚测试；无换边情境保持既有行为，涉及新碰撞的预期差异逐项记录，不能粗略移除旧回归断言。

第三批再给明确需要穿越的角色技能或投技配置短时穿越/换位；如决定加入通用前滚，需要独立动作、受击/被投规则、收招风险、设备操作与美术，不能直接复用普通U冲刺作隐式升级。

玩法与显示验证通过后，单独做“站位与换边”教学：看站位→前跳换边→恢复行动后转身→识别新的前后方向→最后才做换边后的防御。防御课原四目标保持。
