# 第一版双人测试候选

本版是可导入的测试候选，模拟器验证与真机性能验收分开。保留所有旧包，无选人复测包可单独先测。

## 安装

导入本目录时间戳命名的 A 界面包；继续使用先前的 B 图元模板。Lua 中 `PIXEL_TEMPLATE_INDEX=1073741845` 对应用户截图的 B 容器。如果重新导入 B 后索引改变，需要填新的**客户端模板容器**索引。

脚本随 A 包挂在内部 `FighterDemo` 容器上。不要挂到 B 的 Pixel。单独覆盖 Lua 时，使用 `delivery.json` 中的脚本映射路径。

完整版本必须按 [节点图接线思路](节点图接线思路.md) 增加 FighterSelect/FighterFlow，并给 Join/Joined 加 Epoch。GIA 不包含官方节点图。

## 使用

开始双人对战 → 各自选择角色 → P1 选择场景 → 双方确认 → 加载所选角色 → 双方加载完成后开战。单角色三局两胜。结算“再战”需双方投票；重新选人或返回会通知另一端退出当前比赛。

PC：A/D 移动、S 蹲伏、空格跳跃、J 轻攻、K 重攻、L 防御、E 特殊技、Q 必杀。S+J 下段、前+K 上段、S+K 升空。保留可选搓招。H 指令表。PC 不显示摇杆和攻击按钮。

手机：左侧八方向摇杆，右侧轻/重/跳/防/E/Q；顶部“指令”与“退出”。指令表不暂停联机模拟。

## 加载与释放

- 菜单运行时池：两份 504 图元预览池 + 两份 103 图元头像池，共 1,214 张动态图片；11 个小卡片头像为静态小素材。
- 战斗只扩到当前两名角色各自最大姿势数，迪卢克才增加 338 图元火鸟。选不同角色常驻量不同，见 `resource-budgets.json`。
- 示例刻晴/迪卢克：1,369 + 2,335 + 338 + 206 = 4,248 张动态图片。若双方都是岩盔丘丘王则更高；分批加载不等于降低单个复杂角色上限。
- 未选角色姿势以紧凑字符串保存，进入战斗按时间预算展开所选角色数据；退出释放展开表和战斗池多余实例，留下小菜单池。下一回合同角色不重复加载。
- 每次创建最多 24 个实例，每帧工作预算约 2ms；姿势展开另设批次，同样受时间预算限制。进度包含展开与创建，是真实工作量，非固定计时动画。
- 全部资源仍随 Lua 交付，文件读取/解析仍有成本；不把它描述成从外部磁盘按需下载。Lua/GIA 大小见交付报告。

## 新角色范围

新增九名角色各有 12 个独立关键姿势；蓄力、起身、浮空受击等过渡复用部分关键姿势。现有刻晴/迪卢克关键姿势保留。新角色规则为格斗改编，必杀一次命中判定，具体见工作区的角色设计记录。

已检查：选人/加载/退出后再进入，11角色动作入口，H，手机3屏幕比例，三局两胜结算/双方再战，原两角色防御/浮空/回滚，以及新角色部分特性。

未真机验收：手机加载时间和帧率、官方节点新协议、复杂动作的画面抖动与平衡。当前为关键姿势测试动画，细致中间帧与场景美术仍可继续打磨。回滚最大预测仍有限，网络输入断续时“暂停预测”仍可能出现，不能将这次加载优化当作网络卡顿已全部解决。
