## 动作与技能标准

1. **先参考，后设计。** 查原作A/E/Q和可见动作，查看格斗游戏的重心、起手、释放、收势和魔法特效。公开截图、视频、抽帧与本地资料分别记录来源；打不开或没看完不能写成已观察。DNF Duel与DNF Online不是同一个参考，不能替代用户要求。
2. A从原作多段普攻选适合横版的动作，E为特殊技，Q为必杀；保留角色辨识度，不把所有人改成同一套拳脚。岩盔丘丘王是敌方角色，按其动作改编，不声称有原作可玩角色E/Q。
3. 场上技能与待机、移动保持**同一镜头、比例、朝向和脚底基准**。正面大招图、半屏立绘不能充当动作帧。人物单独做动作，特效另做；独立演出插画是否保留不改变这个要求。
4. 完整覆盖：微动站立、移动、蹲伏、站立/蹲伏防御、上下段攻击、跳起/下落/落地、空中攻击、受击、浮空受击、倒地、起身、A/E/Q、胜利动作候选。探针必须能演示这些状态，不能只提供攻击。
5. 补帧用于改善准备→出手、有效刀路、收招→待机、落地、倒地→起身等跳变；不盲目统一加帧。当前48张模板和A/E各8张是制作结构，**不是用户要求所有角色必须48张，也不是整套流畅动画已完成的证明**。
6. 武器/手势/支撑脚/髋肩关系稳定；慢放能分清起手、出手和收招。不能用旋转同一张图冒充挥击、用巨大特效遮错误动作。
7. 攻击动作、有效距离和技能特效范围一起设计；视觉外缘与真实判定分开。平衡依据实际接触与角色特色，不把当前探针数值当正式定案。

已确认的技能方向：刻晴E投雷楔后瞬移，Q多方向斩视觉按一段主要命中处理；迪卢克E三段前向火刀、Q火鸟。那维莱特喷水、纳西妲智慧殿堂等需保留意象，但按格斗实际改编，不照搬原作领域。

## 必杀、状态型技能和演出

用户认可的优先标准：条件满足→起手→首击真实判定→命中才进入双方攻击/受击演出→尾段结算主要伤害→受击/倒地及收招。防住、打空各有分支，不能无条件锁对手。刀光数量不等于伤害次数。

领域难以直接表现，当前优先统一上述命中演出方案。动画后改变攻击形态是另一个保留方向；状态型Q需要相应待机、移动、普攻等配套动作，**尚待讨论，不能只做施放图就宣称状态系统完成**。本地60逻辑帧演出是候选参数，不是所有角色的已确认时长。

入场/胜利属于先做加法、最后按成本减法的方向。入场具体方案需要讨论确认：刻晴雷楔先到、电光闪现就位；迪卢克火鸟先到、炸开后在落点出现。入场不产生攻击判定。已有胜利关键姿势可作候选，但不能宣称用户已确认最终演出。

## 特效要求

- 当前特效过度拉伸、质量不足；不靠把普通效果放大到半屏表现必杀。
- 人物动作与特效**独立素材、独立时间轴、独立存储**。特效可绑定手、武器、胸前、脚底、对手或固定场地点；投射物离手后独立运动。
- 探针支持单独预览特效、绑定位置、偏移、缩放、朝向、播放/暂停/重播和导出。现有绑定点是姿势估计，之后需逐帧标定。
- 预备、出手、飞行/持续、命中、防御、残留分开；空挥不得显示命中爆光。装饰光不改变判定范围。
- **具体技能特效稍后讨论。** 现有四类结构试验不能当角色最终特效；当前先纠正人物与动作，不继续盲目批量制作最终特效。

## 探针及每批交付

动作探针是本阶段主要可查看产物：选角色、看全部状态与动作、慢放/逐帧、正反方向、无特效、轮廓、近中远、命中/防住/空挥、特效绑定、必要数据。新旧版本可对照，错误版标为缺陷，不作为默认通过版本。

每批记录名单和逐角色进度：身份参考→比例母版→关键姿势→连接帧→拟合→探针→抽样检查→缺陷/返修。用户允许抽样，**不意味着被指出错误的身份和比例也可以跳过检查**。有多少完成报多少，不以一位代表整批，也不以生成图数量代替完成。

保留实际提示词、原图、逐帧、锚点、帧时长、事件与版本记录；用户新修订必须进入下一次提示词。正式战斗接入和GIA交付另有验收，不把探针候选当可安装包。

## UI、比赛和场景的既定目标（不因本轮动作制作遗失）

双人优先；双方各选三位，依次用于 **ROUND 1、ROUND 2、ROUND 3**，三局两胜，提前两胜结束。游戏内不写R1/R2/R3简称；不是一局内接力，接力留后续补充。若娜瓦暂不做。

选人：两个中央展示框靠近；左右各三栏位引导选满三人；头像网格能扩展到四五十人、分页；名字在已选栏和展示处；双方红/蓝标识，其他头像灰；字号不遮挡，重复提示删除，按钮有边框、圆润且风格化。选定后才构建人物预览，不让所有候选持续动画。地图不在选人页展示，由权威端随机并同步。

HUD：头像、血量、能量、胜场、计时和必要状态；删除多余说明，H打开指令表。PC不显示手机摇杆/按钮；手机按钮和摇杆简化、美化。现有键位属于实现候选，可按格斗游戏继续简化，不能把候选键位写成永久要求。

场景：略俯视地面区块，与横版角色和背景衔接；背景清晰，恢复关键地标，不能用模糊背景和一根平线地面敷衍。结算、再战、退出等有联网交互；选人同步、双方加载就绪和开战门槛必须能实际测试。

单人AI是后续设计目标，应按角色动作、距离、反应和行为设计；不能把随机按键当完成AI。本阶段先把动作流程和第一批修正做稳。

## 性能、存储和联网边界

手机加载非常慢是用户真机反馈。只按当前场出战角色加载，切场黑屏读条、退出卸载；多人阵容不默认全素材常驻。后续角色选择黑屏加载或预加载需依据预算，不能无上限后台创建。黑屏底部进度条、派蒙动画和真实进度必须运行；不能以假进度掩盖失败。

存储需优化：帧表引用/复用、共享图元池、紧凑数据、按需读取；区分压缩文件体积、运行时内存、实际控件数、可见数量和换帧写入。gzip文件存在不等于千星已支持解压；隐藏不等于卸载。

联机要保留已验证知识：共享变量实体与节点挂载实体区分；玩家列表索引0/1与Slot 1/2区分；席位、准备/开战、输入转发、回滚与等待预测分开诊断。静止玩家也应按协议发输入，不能因没操作导致对方一直等；回滚/伤害事件按逻辑帧和唯一事件处理，不能靠本地动画回调结算。协议变化需同步Lua和节点说明。

最终正式交付需要GIA安装说明、引用/客户端控件索引绑定说明、Lua放置说明和节点安装思路；文件按用户指定 `gpt_时间戳_说明` 命名，放千星目录时确认实际目标及文件存在。不能把模拟器服务逻辑冒充已生成官方节点图。

## 制作流程门槛与禁止事项

**身份核验/正确旧版复用→同场比例母版→无特效关键动作→连接帧→独立特效绑定→实际尺寸拟合→探针抽样→缺陷返修→优化战斗测试版→配套GIA/Lua/节点说明。** 当前先处理烟绯、可莉的比例，复用正确丘丘王，再拓展其余第一批。复用不意味着倒地、起身和连接动作自动齐全，缺失动作仍需按正确母版补足。

失败门槛：身份错误、大头偏离统一画风、裁头/裁武器、跨格粘连、假透明、脚底漂移、动作阶段不可读、特效遮角色、错将打空/防住锁入必杀。发现问题先改母版，不继续基于错误母版生成整套。

用户安全要求：**不乱删电脑文件，不读取项目以外个人信息**；原素材与错误候选保留、版本化。必要游戏参考操作在用户授权范围内执行，不扩大为任意外部操作/发布授权。生图额度用尽时整理并接入已完成资产，明确剩余缺口，不假称整批完成。
