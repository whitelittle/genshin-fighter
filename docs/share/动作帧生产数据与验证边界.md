# 动作帧生产数据与验证边界

适用：像素UI动作素材的本地生产、探针与矩形运行数据。此文仅记录通用技术，不包含项目角色、名单或设计决策。

源图、单帧裁切定义、拟合数据、播放序列、战斗事件与验收结果分别保存。提示词记录实际提交版本，失败返修保留。不要用一次脚本成功把所有图片标记为通过。

多姿势源图不能默认均分。透明通道和连通区域可辅助定位实际主体，但可能把离手武器、饰物或相连角色错误分组；主体数量、边缘、跨图交叠和附属物需复核。独立姿势图片是运行时优先交付形式。自动脚底和骨盆估计是候选元数据，不是骨骼识别结果。

透明像素可能仍有RGB；只看预览底色不足以判定背景。检查alpha零值、部分透明与边缘分布。二值像素转换的alpha阈值要与颜色、轮廓一起验收，不能把阈值提高称为完整语义抠图。

显示帧数量与60Hz逻辑时长分开。连接帧必须实际存在，不能把保持同一姿势写成补帧。起手、有效、收招按逻辑时间分配帧保持，跳过渲染帧不能漏掉事件。事件按动作实例与逻辑帧确定，不能等待图片加载完成或动画播放结束才结算。

矩形拟合重建相等，只证明转换后的像素被正确表示；不证明原图正确、动作连贯、持械稳定、角色一致或真机性能。负载报告区分单帧峰值、共享池、双演员峰值、全帧数据、可见/常驻、换帧写入和销毁。压缩运输文件不表示目标平台已支持对应解码。

建议验证层级：数据完整性 → 实际尺度视觉 → 连续与逐帧播放 → 接触分支模型 → 正式战斗及同步 → 真机负载。每层独立记录通过范围与待验证项；不要把本地画布成功写成联机或真机通过。
